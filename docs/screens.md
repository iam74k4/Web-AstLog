# 画面一覧

公開は6種類（トップのページの並び・全体・メンバー個別・作品1件・機械に読ませる2本・
画像）で、ページの数は構成しだいに変わる。管理は概要・資源の編集・設定・プレビュー。ルートの登録は
`src/routes/public/routes.ts` と `src/routes/admin/index.ts`（描くのはその隣の資源ごとの
モジュール。一覧は README の「構成」）。

どの応答にも（公開・管理・404・500・リダイレクト）`src/index.tsx` のミドルウェアが
CSP（`default-src 'self'; script-src 'none'; object-src 'none'; base-uri 'none';
form-action 'self'; frame-ancestors 'none'; img-src 'self';
style-src 'self' 'unsafe-inline'`）・`X-Content-Type-Options: nosniff`・
`Referrer-Policy: strict-origin-when-cross-origin` を付ける。公開 HTML の `script-src` だけは
装飾開始 helper の exact SHA-256（`MOTION_CSP`）に替える。自分の CSP を持つ
`/images/*` はそのまま（上書きしない）。`/admin/*` はさらに `Cache-Control: no-store`。
Worker を通らない `public/` のファイル（`/app.css`・`/admin.css`・`/preview.css`・`/assets/…`）には
`public/_headers` が nosniff・Referrer-Policy・`default-src 'none'; sandbox` を付ける。
3枚の CSS にはさらに `Cache-Control: public, max-age=31536000, immutable`（HTML が
中身から作った版つきの URL `/app.css?v=…` で読む。`src/ui/components.tsx` の `Stylesheets`）。

訪問者の GET（セッションのクッキーを持たない）は、公開ページの写し（Cache API。
`src/lib/page-cache.ts`）を通る。置くのは 200・301・302・404 で、管理画面の保存が
内容の版（KV の `site:version`）を上げると外れる（ほかの場所の訪問者に届くまで
最大 60 秒ほど）。デプロイでも全部外れる。D1 が例外を投げたら、いまの版の写しが
あればそれを返す（管理画面で書いたあとの写しは出さない——下書きに戻した作品が障害の
間に戻らない）。通らないのは `/admin`・`/images/*`・`/robots.txt`・最後の語に「.」を
含む URL（`/sitemap.xml` を除く）と、`set-cookie` を持つ応答・`private` か `no-store` を
持つ応答（ログイン中の `private, no-store`）。行き先がデータで変わる 301（前の slug・
前の区分・1人のサイトの `/team` と `/profile`・個人ページの Contact・前の個人ページの続き・
前の本文の画面）は `Cache-Control: no-cache` で、
ブラウザに覚えさせない（写しから返すときも付け直す）。応答の `x-astlog-cache` が `hit` / `miss` / `stale`。

## 公開側

誰でも見られる。出すのは `published = 1` の行だけ。色と見出しの書体は、管理の
[見た目](#見た目)で選んだものがそのまま全ページに効く（並べ方＝骨格は1つで、選ばせない）。

骨格は **上の帯・本文・足元**（`src/ui/Layout.tsx`）。上の帯はロゴ（ΛSTLOG。入口へ）と目次と、
ログイン中だけ「管理画面」の入口。足元は名乗り（1人のサイトなら名前・職種、どのサイトでも一言）と
GitHub / メール、著作権表示と「全体を1ページで見る →」。足元はどの幅でも畳まない。

公開ページは**節ごとに1ページ**（入口・Projects・Profile・Contact と打ち込むブロック）で、
**普通に縦にスクロールする**。目次の1行が1ページで、上の帯はページの上に
貼り付き（`position: sticky`）、どこまで読んでも見えている。ページのあいだを行き来する
手は目次と、ページの中のリンク（入口の「一覧で見る →」・一覧の行・
「← 一覧に戻る」）だけ。以前は
「1画面に1つぶんだけを収め、ページはスクロールしない」を不変条件にして、入りきらない
ぶんを次の URL（`/projects/2`・`/members/<slug>/about` …）に割り、画面の底の左右の手
（ページャ）でめくっていた。持ち主が実際に触って「スクロールできず、底の左右の手でしか
めくれないのが面倒すぎる」と判断してやめた。前の URL は新しい場所へ 301 で送る（貼られた
リンクを殺さない）。移動は普通のフルページ遷移で、内容と導線は JavaScript なしで成立する。
実行 script は装飾開始 helper 1本だけで、CSP はその exact hash だけを許す。ページを移るときは CSS の view transitions
（`@view-transition`）で短く切り替わる——上の帯は動かず、一覧の行の題は作品のページの見出しへ
つながる。入口と締め（Contact）は画面の残りいっぱい（`--cover-h`）を下限にした表紙。

表は `src/routes/public/routes.ts` の**登録順そのまま**。`/:screen` と `/:screen/:page`
は1語・2語の URL を何でも拾う catch-all なので、固定の URL は必ずその前に並ぶ。

| ページ | パス | 出すもの | 中身が無いとき |
| --- | --- | --- | --- |
| 全体 | `GET /all` | 公開中のブロックを全部、1ページに縦に積んで | その節ごと出さない。見出しだけ残さない |
| プロフィールの別名 | `GET /profile` | 1人のサイトのプロフィール（目次の「Profile」の行き先 `/members/<slug>`）へ 301（行き先がデータで変わるので `no-cache`） | プロフィールの無いサイト（2人以上・Team を置いていない）では 404 |
| トップ | `GET /` | 並びの先頭のページ（ふつうは Hero）。先頭が1人のサイトのプロフィールなら、そこへ 302 | 置いたものが全部空なら「まだ何も置いていません」 |
| メンバー個別 | `GET /members/:slug` | 名札（顔・名前・肩書きと所在地）と大見出し、2人以上のサイトならこの人の一覧への帯、その下に About・Skills・Career の小節（`#about` `#skills` `#career`） | 下書き・不明な slug は 404。前の slug（管理画面で変えたもの）は、いまの slug へ 301 |
| 前の個人ページの続き | `GET /members/:slug/:rest` | `about` `skills` `career` はこのページの小節（`/members/<slug>#about` …）へ 301。小節が無くなっていればページの頭へ。`contact` はサイトの `/contact` へ 301 | 知らない名前は 404。前の slug はいまの slug の同じ続きへ 301 |
| 割っていたころの続き | `GET /members/:slug/:rest/:page` | 同上（`/members/okazaki/career/2` → `#career`） | 番号の形（1始まりの数）でなければ 404 |
| 作品1件（個人開発） | `GET /apps/item/:slug` | その作品のページ（一覧の行を開いたもの）と、画像が2枚以上なら縦ギャラリーの小節「Screenshots」（`#screenshots`）、本文があればその下に小節「Story」（`#story`）。頭に「← 一覧に戻る」（一覧のその作品の行 `/projects#item-<slug>` へ） | 下書き・不明な slug は 404。前の slug（管理画面で変えたもの。`item_slug_redirects`）は、いまの URL へ 301 |
| 前の本文の画面（個人開発） | `GET /apps/item/:slug/story` | 作品のページの `#story` へ 301（本文が無くなっていればページの頭へ） | 下書き・不明な slug は 404。前の slug はいまの URL の `…/story` へ（そこで `#story` へ） |
| 作品1件（業務） | `GET /works/item/:slug` | 同上 | 1語目と種類が食い違う URL（区分を変えた作品の前の URL）は、いまの区分の URL へ 301 |
| 前の本文の画面（業務） | `GET /works/item/:slug/story` | 同上 | 同上 |
| 以前の一覧 | `GET /apps` `/apps/:page` `/works` `/works/:page` | 同じ区分で絞った `/projects` へ 301（`?member=` は引き継ぐ） | — |
| クローラへの指示 | `GET /robots.txt` | `text/plain`。`/admin/` だけ外す | — |
| URL の一覧 | `GET /sitemap.xml` | `application/xml`。公開中のページを数え上げる | — |
| 画像 | `GET /images/avatars/…`<br>`GET /images/items/…` | KV に入れたアバターと作品の画像。キーの形（置き場 / 英数字で始まり英数字と `. _ -` だけの名前）に合わないものは読みに行かない（KV のキーを外に開く口なので、置き場の外は読ませない）。どの応答にも `X-Content-Type-Options: nosniff` と `Content-Security-Policy: default-src 'none'; sandbox`（同じオリジンで配るので、画像のふりをした文書が直に開かれても走らせない）。content-type は KV に入れた型が5種類（PNG・JPEG・WebP・AVIF・GIF）のどれかならそのまま、それ以外（以前の SVG・HEIC）は `application/octet-stream` の添付（`Content-Disposition: attachment`） | 該当なし・形が合わないものは 404 |
| ページ | `GET /:screen` | そのブロックのページ（`/projects` `/team` …）。中身は全件で、割らない。1人のサイトの `/team` はプロフィールへ 301 | 無いページ名は 404。ページの名前の形（`hero` `projects` `team` `contact` か `block-<id>`）でなければ D1 に聞かずに 404 |
| 割っていたころの続き | `GET /:screen/:page` | 同じページ（`/projects/2` → `/projects`）へ素の 301。query（絞り込み）は付けたまま | 名前の形か番号の形（1始まりの数）が合わなければ 404 |

作品の恒久リンクが3語なのは、catch-all（1語・2語）と取り合わないようにするため。
2語（`/apps/<slug>`）にすると、割っていたころの番号と作品の名前が同じ位置で取り合い、
slug が数字の作品を作れなかった。一覧を Projects の1つにまとめたあとも、恒久リンクは
区分の語（`apps` / `works`）のまま変えていない——貼られた URL を動かさないため。
前の本文の画面（`…/story`）と前の個人ページの続き（`/about` …）は、転送するためだけに
ルートが残っている。

404（未定義の URL）と 500（例外）は、ルートではなく `src/index.tsx` の
`notFound` / `onError` が受ける。マークと戻り導線だけを出す。説明は訪問者の
言葉で書く（404 は「URL が変わったか、打ち間違えているかもしれません。」）——
`slug` のような管理画面の言葉は、ここに着いた人には読めない。

登録順は散文だけでなくテストが守っている（`test/public.test.ts` の「URL の登録順」が
Hono の `publicRoutes.routes` を読み、catch-all が最後の2本だけであることを見る）。

絞り込みは query で足す。どのページにも付けられる。

| query | 効く先 | 例 |
| --- | --- | --- |
| `?kind=app\|work` | Projects（個人開発 / 業務） | `/projects?kind=work` |
| `?member=<slug>` | Projects | `/projects?member=okazaki` |

知らない区分・公開中に居ない slug は、絞り込みとして扱わず全件を出す。絞り込みに
並ばないもので絞り込むと、外す手がページから無くなるため。同じ理由で、区分の絞り込みが
並ばないサイト（項目が片方の区分にしか無い）では `?kind=` を、公開中が1人の
サイトでは `?member=` を読まない（名前の絞り込みは2人以上いるときだけ並ぶ）。
一覧を持たないページ（Team など）には絞り込みを付けて回らない。絞り込みは目次の
Projects の行き先にも同じものが付いて（目次から一覧へ戻っても外れない）、canonical
には付けない（同じ中身の取り出し方なので、組み合わせのぶんだけ URL を数えさせない）。

`all` はページの名前としての予約語。決まった中身のブロックの key
（`hero` `apps` `works` `team` `contact`）とも、打ち込むブロックの `block-<id>`
とも衝突しない。**固定のルートは `/:screen` より前に登録する。** あとから下に
足すと、一致が catch-all に吸われて、そのページだけが静かに 404 になる。

先頭のページは `/` と `/<slug>`（`/hero`）の2つで開ける。canonical は `/` に
そろえ、2つ目からはそのページの URL が正。題も説明文もページごとに変える（同じ題の URL が
並ぶと、履歴から選び直せない）。`<title>` の組み方は `src/routes/public/meta.ts` の
`pageTitle` 1本で、ページの名前を「 · 」でつなぎ、最後に「 — AstLog」:

| ページ | `<title>` |
| --- | --- |
| 入口 | 1人のサイトなら「岡崎 昂功（System Engineer） — AstLog」（肩書きが空なら名前だけ。「（）」を出さない） |
| 節 | 「Projects — AstLog」。割っていたころの数え方（「2 / 4」）はもう無い |
| 名前の無いページ | ひとことは一文の頭、見出しを空けたメモは最初の段落の頭（30 字で切る） |
| 個人ページ | 「岡崎 昂功 — AstLog」 |
| 作品1件 | 「AppMixer — AstLog」 |
| 全体ページ | 「岡崎 昂功（System Engineer） · 全体 — AstLog」（入口と同じ題にしない） |

以前は題を節の名前だけから作っていて、ひとことのページは入口と同じ題だった。
**サイトの名乗りの構造化データ（JSON-LD）は並びの先頭のページにだけ載せる**——同じ
名乗りがページの数だけ並ぶと、どれが本体か決められない。1人のサイトのプロフィールは
並びの途中なので載らない（先頭に置いた構成でだけ、そのページが名乗る）。2人以上の
サイトの個人ページは、その人の `Person` を載せる（そのページが何の URL かを言う）。

**足元はどのページでも名乗る。** 1人のサイトなら、入口も含めてどのページ
（入口・Projects・個人ページ・作品・Contact・`/all`）でも、足元に名前と職種を出す。入口の
大見出しはその人の一文（名前ではない）なので、同じ名前が2度は並ばない。2人以上のサイトでは
足元に名前を出さない。Contact のページでは足元の GitHub / メールを出さない（本文の手と同じ
行き先が2組並ぶ）。

`<meta name="description">` と `og:description` は、**そのページに実際に出ている文字**
から作る（`src/routes/public/meta.ts` の `DESCRIPTION_MAX` は 110 字。超えたら末尾を `…`
にして切る）。入口＝名乗り、Projects＝件数と区分とそのページの行の名前（実績値の
ある行は実績値も。絞り込めば絞った行だけ）、Team＝名前と職種、個人ページ＝大見出し
（無ければ紹介文の1段落目）、作品＝説明（summary）、
打ち込んだブロック＝見出しと行、
`/all`＝実際に描いた節の名前。固定の文を書かないのは、中身を足した日に説明文だけ
古くなるため。

Contact はページに出ている誘いの1文（サイト設定の `contactLead`）をそのまま使う。
手の字（アドレスと「メールを送る」・GitHub）だけでは、検索結果でも貼られたカードでも
何のためのページか分からない。

共有カードの画像（`og:image`）は、作品のページで画像があればその作品の画像
（絶対 URL。種類は経路の拡張子から、寸法は上げたときに読んだ `items.image_width` /
`image_height`。分からないものは名乗らない。AVIF は貼り先が読まないのでサイトの1枚に
戻す）、それ以外はサイトの1枚（`/assets/astlog-avatar.png`、1024x1024 PNG）。`twitter:card` は
画像の寸法で決め、横長で 300x157 以上なら `summary_large_image`、それ以外（サイトの1枚・
縦長・寸法が分からない）は `summary`。サイトの1枚は推奨の 1200x630 に届かないので、
貼り先は小さな正方形のサムネイルを出す。**足りないもの: 1200x630 の PNG 1枚**——置いたら
`src/ui/Layout.tsx` の `SITE_IMAGE` を差し替えるだけでよい（札は寸法から決まる）。

### 機械に読ませる2本

`/robots.txt` は `User-agent: *` / `Allow: /` / `Disallow: /admin/` と、絶対 URL の
`Sitemap:` 行。相対では書けない（クローラが読まない）。

`/sitemap.xml` は手で並べた表を持たず、公開ページと同じ式から数え上げる——
トップのページ（`sitePageLinks` の canonical。1人のサイトではプロフィールもここに入り、
`/team` は入らない）／全体ページ `/all`／個人ページ（`memberHref`）／作品の恒久リンク
（`itemHref`）の4つ。作品は URL を組むぶん（区分・slug）だけを引く
（`listPublishedItemKeys`。一覧の行のタグ・リンク・担当は全件ぶん読まない）。
入口 `/` は、並びの先頭がプロフィールの構成（そこへ 302 で送るだけ）でだけ載せない。
載らないのは下書き・0件で消えた節・絞り込み付きの URL・`/admin`・転送するだけの URL
（`/team` と `/profile` の 301・前の個人ページの続き・前の本文の画面・割っていたころの続き）。
同じ URL は1度だけ。**新しい URL の族を足したら、この4行にも1行足すこと。**

どちらも Worker のルートで返す。`public/robots.txt` や `public/sitemap.xml` を
置いてはいけない——`public/` は Worker より先に配られるので、置いた瞬間に静的な
ほうが勝ち、数え上げが静かに死ぬ。

### トップの構成

トップは「決まった部品（ブロック）の並び」で、管理の[構成](#構成)から
置く・外す・前後に動かす。部品の見た目は変えられないので、どう並べても同じ設計の
中に収まる。何も置いていなければ Hero → Projects → Team → Contact の順。

**1つのブロックが1ページ**で、中身は全部そのページに並ぶ（ページは縦に読む）。
以前は1画面あたりの件数（`perScreen`）と字数（`maxChars`）を種類ごとに持ち、入り
きらないぶんを次の URL に割っていた。いま `src/blocks.ts` に残っている数は、名前と目録の文の
長さ（`MAX_CHARS`）だけ。

| ブロック | 中身 | 出す条件 | 備考 |
| --- | --- | --- | --- |

10 字まで（目次の1行の名前。ひとことを除く）。

入口と締めの星雲は、模様を透過 WebP に焼き、ページでは背景の箱ごと動かす。色は6種類
（mono と iris は共用）。粒と流れる星は65点を元にした固定 CSS の区間を整数の1/60秒へそろえ、
区間ごとの `steps()` で小さい HTML を60回/秒まで動かす。星屑・天体・瞬き・星雲の漂い・
ブラックホールの光はその6刻みの100ms。動きを減らす設定では完成形のまま止まり、
印刷では星系と星空を出さない。底のフェードは下端の帯だけに地の色を重ねる。瞬く星と流星は小さい
HTML の点・筋を動かし、静止した星空と描画を分ける。
星屑は総数600粒まで。奥と手前の外側 SVG に坂の1/4・3/4の代表濃さを掛け、奥ほど淡くする。
内外とも mask は置かない。公転・半面の切り取り・画面 px 単位の太さは保つ。
背景と星系は完成形で出し、継続動作は load の1200ms後から350ms間隔の小さい群で始める。
helper が共通の時計にそろえて全群を始めたら処理を終える。JS 無効時は通常の CSS 動作。

目次は、実際に出た節だけを、出た順に1行ずつ載せる（組むのは `src/lib/sequence.ts` の
`tableOfContents`。先頭の Hero へはロゴで戻る。1人のサイトのプロフィールは「Profile」の1行）。**番号（01〜）は
振らない**——目次の番号はブロックの並び順でしかない。いま見ているページの行に印
（`aria-current="page"`）。作品のページでは載っている一覧（Projects）の行に、個人ページ
では Profile（1人のサイト）か Team（2人以上）の行に印が付く。英字だけの行き先は等幅の
小さな大文字の札（`lang="en"`）、印は頭の四角。目次は上の帯の右に1行で並び、溢れたら横に
送る（右端をぼかす）。帯は印の付いた行き先が見える位置で開く（`scroll-initial-target`。
知らないブラウザは左端で開く）。`/all` の目次は目に見える見出しだけを並べ、折り返す。ページは横に動かない。

**画面の底のページャ（← 前 / 次 →）は無い。** ページのあいだを行き来するのは目次と、
ページの中のリンク（入口の「一覧で見る →」と札・一覧の行・「← 一覧に戻る」）。以前はページャで並びを
一周できたが、節を画面ごとに割った続きをめくるための手で、1ページにまとめたので要らない。

見出しを持つ節は `role="region"` と見出しと同じ `aria-label` を持つ。`main` の直接の
子になる箱は `src/ui/components.tsx` の `Screen` / `Hero` だけが作る。節に `tabindex` は
付けない（ページそのものがスクロールするので、節は止まる先ではない。以前は節が溢れの弁
`overflow: auto` で、WebKit では弁にフォーカスできないために付けていた）。ページの中の
id（`#about` など）へ送ると、見出しは貼り付いた帯の下に止まる（app.css の
`scroll-padding-top` と `:root` の `--top-clear`）。

**節は上揃え。** 見出しはどのページでも同じ高さ（帯の罫線から本文の上の余白 `--page-pad`
ぶん下）から始まる。上下中央に寄せていたころは中身の量で見出しの高さが跳ねていた。
上揃えにしないのは Hero（入口の表紙）と Contact（字は図の下。900 以上は表紙の底へ）だけ。`npm run check:fit` が、
同じ書体・寸法・姿の中で見出しの上端がそろっていることを測る（最初の子が節のページだけ。
作品のページは見出しの上の「← 一覧に戻る」の上端）。

### 全体ページ

`GET /all` は、公開中のブロックを全部1ページに縦に積んで出す。**canonical は自分自身**。
節は `#projects` のような id で並ぶので、ページごとの URL（`/projects`）と同じ節を
アンカーでも指せる。この1本が受け持つのは次の役目。

- 印刷。1回で全部が紙に載る
- Ctrl-F とブラウザ翻訳。ページをまたがずに全文を探せる・訳せる
- オーナーが全体を通しで点検する
- ページごとの組み立てが効かない環境での退避先

canonical を `/` にしていたころは、中身が全部ある唯一のページを「作品を1件も
含まないトップの複製」として申告していた——index に載るのが中身の薄い準重複の
ページばかりで、完全版が載らない、という逆の形になる。ページごとの URL はそれぞれ
自分を正と名乗り、`/all` も自分を名乗る。

作品の本文（ページごとの URL では作品のページの小節 `#story`）も、ここでは
Projects の節の行の下に、作品名の `h3` に添え「Story」の小節で並べる
（`ItemStories`。テンプレートの欄の小見出しはその下の `h4`。本文の無い作品は並べない）。行の中に入れないのは、行が面ごと
作品のページへのリンク（題の覆い）だから。Projects の節に絞り込み（すべて / 個人開発 / 業務）は
置かない——中身を全部載せる場所で、絞り込みの手は `/projects?kind=…` へ移るリンクになり、
「すべて」の印が別のページを「いまのページ」と名乗っていた。

節を縦に積んだ1本の文書なので、「ページの外枠」（表紙の高さ・貼り付く帯）はここには
当てない（目印は `body[data-whole]`。上の帯は頭にあるだけで、目次は折り返す）。

1人のサイトでは、Team の節の代わりに **Profile の節**（`#profile`、目次も「Profile」）を
置く。中身はその人の名札・大見出し（大きな一文）・紹介・技術・経歴で、個人ページと同じ
もの。見出しの段は Hero の `h1` → Profile の `h2` → About / Skills / Career の `h3` →
技術の小見出しの `h4`。中身の無い小節は見出しごと出さない（個人ページの About は空でも
「準備中です」を出すが、あれは名札の下に何も無いページを作らないため）。部品は個人
ページと同じもの（`src/ui/components.tsx` の `ProfileWhole`）。

行く道は2本ある。公開側はどのページの足元にもある「全体を1ページで見る →」（どの幅でも
畳まない。同じ行き先を本文には置かない）、管理側は「構成」のヘッダの
「全体を1ページで見る ↗」。`sitemap.xml` にも載るので検索からも届く。

### メンバー個別ページ

`GET /members/<slug>` の1ページに、上から縦に並べる（`src/routes/public/member-page.tsx`
の `memberPage`）。1ページ = 1ドキュメント。

| 小節 | 出すもの | 出す条件 | 見出し |
| --- | --- | --- | --- |
| 名札（Hero） | 顔・名前・肩書きと所在地、大見出し、その人の天体、その人だけの GitHub / メール、2人以上のサイトならこの人の一覧への帯 | 常に | 大見出しが `h1`（無ければ名札の名前が `h1`） |
| About（`#about`） | 紹介文 | 常に。空なら「準備中です」 | `h2` |
| Skills（`#skills`） | 技術。塊の中は経験の添えごとの行（添えは行の頭に1度だけ、`dt` / `dd` の組。添えの無い項目は最後の行） | 書いてあるときだけ | `h2`。塊の小見出しは `h3` |
| Career（`#career`） | 経歴 | 書いてあるときだけ | `h2` |

Members の「天体と色」でブラックホール・土星・海王星・月・太陽を選ぶ。色はサイトの色の継承か、
既存の7色プリセット。個人ページの表紙に大きな天体、名札・Team・全体の Profile に小さなシンボルを
置く。写真を置き換えず、本文や操作の文字は白を保つ。公開中が1人なら入口・Contact の中心にも反映する。
0人・複数人の入口はサイト共通のブラックホール。保存前プレビューは同じ描画を使い、D1/KV に書かない。
省略された選択は編集時に既存値を保ち、新規はブラックホールとサイトの色。未知の入力は下書き・保存・
プレビューとも400で選択欄を開く。DB の未知値は描画時に既定値へ戻す。

以前は4つを別々の URL（`/members/<slug>/about` …、長ければ `…/career/2`）に割り、画面の
底の左右の手でめくっていた。持ち主が「Profile → About → Skills と、底の左右の手でしか
進めないのが面倒すぎる」と判断して1ページにまとめた。前の URL は小節へ 301
（`/members/<slug>/about` → `/members/<slug>#about`。小節が無くなっていればページの頭へ）。

**個人ページはサイトの並びの一部。** 上の帯と目次と足元はサイトのままで、個人ページ専用の
ものに入れ替えない（入れ替えると、Team のカードを押した先が別のサイトに見え、Team へ
戻る道も無くなる）。並び方は人数で2つに分かれる。

**1人のサイト（Team を置いているとき）: プロフィールがサイトの並びに入る。**
Team のページは作らず、その位置にこの人のページが並ぶ。目次は「Profile」の1行で、
このページでその行に印。

```
入口 ── Projects … ── Profile（/members/<slug>） ── Contact    ← 目次の行
                         名札 → About → Skills → Career（縦に読む）
```

1枚の細いカードだけの Team のページは、複数いる前提の器に1人しか入っていないことを
ページ1枚ぶん使って告知していた。中身はカードを押した先のほうにあるので、Team の位置に
中身そのものを置く。`/team` はこのページへ 301（2人目を公開すると Team のページに戻る。
行き先がデータで変わる転送なので、ブラウザには覚えさせない）。帯（このメンバーの
つくったもの）は出さない——入口の「一覧で見る →」と同じ行き先・同じ件数の手が、サイトに2度出る。
構造化データも載せない（並びの途中。先頭の入口が同じ人を名乗っている）。

**2人以上のサイト: Team から入るページ。** 目次はサイトのまま（Team に印）。Team を
置いていないサイトでは、目次に印の付く行が無い（一覧の行の担当者名から入る）。

- 作品の行はここに複製しない。名札の下の帯から `/projects?member=<slug>` へ送り、
  一覧をその人で絞り込んだページに着かせる。帯の件数は区分ごと（`個人開発 2 · 業務 1`）
  で、その人に項目の無い区分は数えない。どちらも0件か、トップに Projects を置いて
  いなければ帯ごと出さない。1人のサイトでは `?member=` を付けない（Team を置いて
  プロフィールになっているときは帯そのものを出さない）
- 顔は名札（`.nameplate`）にだけ出る。Team のカードと同じ並びで、押した先で
  同じ顔に着く。名前は、1人のサイトなら足元にも出る
- 連絡先はサイトの Contact に合流させた。`/members/<slug>/contact` はそこへ 301
  （サイトに Contact が無ければ 404）。サイトと違う GitHub / メールを持つ人だけ、
  名札の下にその行き先を置く（同じ行き先を2つ置かない）。その札は読み上げの名前で
  その人を名乗る（「青木 春香の GitHub」）——足元のサイトの GitHub / メールと同じ名前で
  別の行き先を指さないため
- 構造化データは `Person`。公開中が1人のあいだは `worksFor` を出さない
  ——トップが同じ URL を `Person` として名乗っているので、書くと1つの URL が2つの型を
  持つ。1人のサイトで Team を置いているときは、個人ページが並びの途中なので載せない

### 作品1件のページ

`GET /apps/item/<slug>`（個人開発）と `GET /works/item/<slug>`（業務）。slug で1件を
名指しするので、並べ替え・公開の切り替え・追加のどれでも指す先が動かない。貼れる URL は
こちら。

- 出る条件は「その作品が公開中」の1つだけ。**トップの構成には依らない**——Projects の
  節を外しても、貼られた作品のリンクは死なない
- 下書きは 404。1語目と種類が食い違う URL（区分を変えた作品の前の URL。
  `/works/item/<いまは個人開発の slug>`）は、いまの区分の URL へ 301。slug を変えた
  作品の前の URL も、転送表（`item_slug_redirects`）を引いていまの URL へ 301
  （どちらも200 で2つ目の URL を作るのではなく、いまの1つへ寄せる）
- 頭に「← 一覧に戻る」（`BackLink`）。行き先は**一覧のその作品の行**
  （`/projects#item-<slug>`。行の id は `itemCardId`）。一覧は全件を1ページに並べる
  ので、何件目かを数えなくてよい。Projects を先頭に置いた構成では `/#item-<slug>`、
  Projects を置いていない構成では出さない
- 作品同士をめくる手（以前のページャ）は無い。隣の作品は、戻った一覧のすぐ隣の行
- 目次はトップと同じページの並びを出し、印はその作品が載っている一覧（Projects）に付く。
  作品のページは目次に並ばない

**中身**

- 見出し（作品名に「業界 / プラットフォーム · 年」の添え。アイコンがあれば見出しの左）の下は**一覧の行を開いたもの**
  （`ItemDetail`）。説明・実績値（`Metric`）・タグ・行き先（`LinkRow`）は行と同じ部品。
  足すのは絵（画像の `Shot`）だけ。一覧から開くと、行の題がそのまま見出しへ動いて大きくなる
  （ページの切り替え。同じ `view-transition-name`）
- その下に本文の小節「Story」（`ItemStory`。`id="story"`、見出しは `h2`、段落は `Note`）。
  中身は個人開発も業務も同じテンプレート（`src/domain.ts` の `STORY_SECTIONS`）——背景・
  取り組み・工夫・成果の欄を、この順で英語の小見出し（BACKGROUND / APPROACH / HIGHLIGHTS /
  RESULTS。`h3`、Skills の英字の小見出しと同じ形）を付けて出す。中身の無い欄は出さない。
  テンプレートより前に書いた本文（`items.body`）は、見出しの無い段落として先頭に出す。
  本文を書いた作品にだけある（空白と空行だけの本文も出さない。見出しと段落に開く式は
  `src/blocks.ts` の `itemStory` 1本）。以前は本文を次の画面（`…/story`）に分けていて、
  説明の下に「くわしく読む →」を置いていた。同じページのすぐ下に続くので、入口の札は外した。
  前の `…/story` は `#story` へ 301（本文が無くなっていればページの頭へ）
- 画像は `figure`（代替テキストは管理画面で書いた `image_alt`）。枠の高さは `--shot-h`
  で、絵は `object-fit: contain` で切らずに縮める。900 未満は見出しのすぐ下、900 以上
  は文の列を左・画像を右に並べ（`.detail--shot`）、枠は文の列と同じ高さまで伸びる
- 画像が2枚以上の作品は、説明の組に絵を置かず、その下の小節「Screenshots」（`ItemShots`。
  `id="screenshots"`、見出しは `h2`）にギャラリーで並べる（メインの画像が先、ほかの画像が
  並び順で続く。同じ画像を2度出さない）。先頭は全幅、900 以上は続きの画像が大小の2列。
  狭い画面では全幅の1列。枠は `--thumb-ratio` で先に決まり、先頭の高さの上限は
  `--gallery-lead-h`、続きは `--gallery-shot-h`。画像は切らずに収め、番号と説明を添える。
  画像と説明の面がリンクになり、原寸を別タブで開ける。Tab で1枚ずつ選び、Enter で開く。
  先頭だけすぐ読み、続きは遅延読み込み。紙でも並びのまま全部を刷る
- 画像は作品のページにだけ大きく出る（一覧のサムネイルは同じ画像の飾りで、`alt=""`）。
  無ければ `figure` を出さず、代わりの絵も置かない（文の列だけ。前は入口の軌道図を縮めた
  星図を置いていて、持ち主が「なんか違う」と外した。一覧の行も同じ）
- 構造化データは `CreativeWork`（name / url / description、画像があれば image を
  絶対 URL で）。名乗りではないので、どの作品のページにも載る（名乗りは並びの
  先頭だけ）。description（`<meta>` も）は説明（summary）のまま。`<title>` と
  `og:title` は「&lt;作品名&gt; — AstLog」、canonical と `og:url` は自分の URL。
  `og:image` は画像があればその作品の画像（上の「共有カード」の段落）
- 行き先（`LinkRow`）は部品の中で `isSafeUrl` を通し、通らない行（`javascript:`・
  頭を省いた相対 URL）は描かない。全部落ちたら行ごと出さない。保存でも弾いているが、
  その検査より前に入った行を呼ぶ側に頼らずに落とす
- 一覧の行は**面ごと**この URL へのリンク（`/all` の行も同じ）。リンクは題の
  1本（`.entry__link`）で、その `::after` が行を覆う。行の中の Repository と
  担当者名は覆いの上に出ていて、それぞれの行き先へ行く。`slug` の無い作品は素の題の
  まま——押せる面にもならず、矢印も付かない（当てにならない URL を出すくらいなら
  出さない）
- 「担当」（個人ページへのリンク）は、一覧の行の担当者名と同じ条件で出す。2人以上
  いるとき、または Team の節を置いていないとき（そうしないと個人ページへの道が
  トップから1本も無くなる）。行き先の1行（`LinkRow`）に「担当 &lt;名前&gt;」として並び、
  サイトの中の行き先なので矢印は `→`・同じタブ（`↗` は外へ出る・別タブの印だけ）

## 管理側

`/admin/*`。ログインが要る。ログインは GitHub / Google の OAuth だけで、パスワードは
無い。書き込み（POST）は送り元も確かめる——Origin → Sec-Fetch-Site → Referer の順に
見て、origin が違えば 403（`Origin: null` も 403）。壁の外のログアウトも対象。
管理画面の応答はどれも `Cache-Control: no-store`（ログアウトしたあと「戻る」で中身を
出さない）。

公開ページからは、**ログインしているあいだだけ**上の帯に「管理画面」が出て、いま見ている
ページを直す場所へ同じタブで送る（行き先の表は [flow.md](./flow.md#公開側)）。訪問者には
出ない。出したページは `cache-control: private, no-store` で返す。

どの画面も、左ナビの足元の「サイトを見る ↗」から公開ページを別タブで開ける。
その下の名前（最後にログインしたアカウントの @ログイン名かメールアドレス）は
アカウントの画面への入口。

以前の初期設定（`/admin/setup`）とパスワードのログイン（`POST /admin/login`）は無い。
`/admin/setup` は GET も POST も 404、`POST /admin/login` は壁に当たってログイン画面へ
303 で戻る（セッションはできない）。最初の owner は、`wrangler.toml` の
`OWNER_GITHUB_ID` / `OWNER_GOOGLE_EMAIL` と一致するアカウントの初めてのログインで紐づく。

一覧・フォーム・確認の3種類だけで、Members・Items・構成をまかなっている。
一覧にフォームを同居させないのは、「どの行を編集中か」が読めなくなるため。
見た目とサイト設定は一覧を持たず、固定の入力項目を同じ画面で編集する。

### 構成

公開ページの並び。行の ↑↓（読み上げは「前へ / 後ろへ」）はそれぞれ
小さな `POST` フォームで、押すと 303 で同じ一覧に戻る（JavaScript は使わない）。

- 行ごとに「**出る / 出ない**」、一覧の頭に「合計 N ページ」を出す。**読み取り専用の
  知らせ**。公開ページと同じ式（`src/blocks.ts` の `blockShown`。中身を行・段落に開く式も
  `blockLines` / `blockTexts` / `blockUnitCount` の1本を公開側と共有する）で、下書きと、
  中身が0件のもの（項目の無い Projects・通る行の無いリンク集）は「出ない」。合計は
  サイトのページ数そのものになる（目次の行と、ロゴで戻る先頭の Hero）
- これを出すのは、「公開」の札だけでは、中身が無くて公開ページのどこにも出ていない
  ことに気づけないため
- 公開中のメンバーが1人なら、Team の行は「公開中が1人のあいだは、その人の
  プロフィール（目次は Profile）に置き換わる」と添える。下書きの行にも添える——公開
  したら何が出るかの知らせなので
- フォームの hint は書き方だけ（「1行に1件。「何を | 補足」」）。行の数や字数の上限は
  無い。見出しの欄には「10 字まで（目次に1行で並ぶ）」
- 行から**公開／下書きを直接切り替えられる**（`POST /admin/blocks/:id/publish`）。
  **公開にするほうは、編集フォームと同じ公開の関門（`src/blocks.ts` の
  `publishErrors`）を通す。** 関門は「published が 1 になるとき」に1か所で、
  新しく書く・編集の保存・このトグルがどれも同じ関数を呼ぶ。トグルが検査を
  しなかったころは、下書きのまま上限の3倍に書き足したメモや、一文を空にした
  ひとことがこのボタン1つで公開になった。止めたらその行の編集画面へ送り、理由を出す。
  下書きに戻すほうは何も見ない。編集フォームからの保存も、「公開する」を外した
  ものは長さを検査しない——検査すると、上限より前に保存された長い見出しを持つ行が
  「引っ込めることすらできない」行き止まりになり、残る手が中身ごと削除だけになる
- 決まった中身のもの（Hero・Projects・Team・Contact）は**1つずつ**。DB の部分一意索引
  （`blocks_fixed_once`）が2行目を拒み、読む側（`publishedBlocks`）も種類ごとに先頭の
  1行だけを採る。二重送信で2組になったころは、同じ URL が並びに2度並び、公開ページの
  画面の底の「次」が自分自身を指して入口から先へ進めなかった
- ヘッダから公開ページを開ける。「サイトを見る ↗」は入口、「全体を1ページで見る ↗」
  は `/all`（公開側からはどのページの足元にもある1本。幅で畳まない）
- 何も置いていないときは、既定の並びで出している旨と「この並びから始める」だけを出す。
  **「足す」はまだ出さない**。今そこに見えている4節は既定の並びで、行としては
  存在しない。先にそれを行にしてから触らせる
- 「足す」には、まだ置いていない決まった中身のもの＋打ち込むもの全種が並ぶ。
  決まった中身のものは押せばすぐ置かれ、打ち込むものはフォームへ進む
- 「外す」は確認を挟む。決まった中身のもの（Projects など）を外しても登録は消えない。
  `blocks.ts` から消えた種類の行も外せる（読む側が無視するだけでは、一覧に残り続ける）

### 見た目

サイト全体の姿を、決め打ちの組み合わせから選ぶ。1画面で2つを選び、保存すると
すぐ公開ページに出る（下書きは無い）。ページの組み立て方（骨格）は選ばせない——上の帯・本文・
足元の1つだけ（以前は左サイドバー / 中央寄せ / 雑誌風の3つを選べた。前に選んだ値が
settings に残っていても読まない）。

| 選ぶもの | 選択肢 | 効く場所 |
| --- | --- | --- |
| アクセント色 | モノクロ / アイリス / ヴァイオレット / エンバー / ミント / スカイ / ローズ | リンク・塗りのボタン・選択中の印・実績値・入口と締めの軌道図。既定のモノクロは字と同じ白（黒い地に白い字とボタン） |
| 書体 | ゴシック / 明朝 / 等幅 | 見出しだけ。本文は読みやすさを優先して据え置く |

選べる値は `src/theme.ts` が正。実際に姿を変えるのは `public/app.css` の
`[data-accent]` / `[data-typeface]` で、**両方に足さないと「選べるのに何も変わらない」ものができる**。
保存済みの値が選択肢から消えていたら、既定（モノクロ・ゴシック）で描く。

## 画面の状態

どれも JavaScript なしで、1往復で成立する。

| 状態 | 出る場所 | 出し方 |
| --- | --- | --- |
| 入力エラー | フォーム | 項目のそばに1行。**打った内容は残す** |
| ログインのやり直し | ログイン | 提供元で断った（「ログインを取りやめました」）・state が合わない / 切れた / 別のタブで始めた・提供元が断った。`?error=` の決まった札だけを読み、文言はサーバーが持つ |
| 入れないアカウント | ログインの戻り | 403。そのアカウント自身の提供元 ID と、持ち主なら直す設定の名前（`OWNER_GITHUB_ID` など）を出す。Google で未確認のアドレスはそう言う |
| 提供元の障害 | ログインの戻り | 502。「GitHub との通信に失敗しました」。トークンは画面にもログにも出さない |
| すべての端末からログアウトした | ログイン | `?out=all` を読んで帯を1本 |
| 一覧が空 | 管理の一覧 | 空の表を出さず、「＋ 最初の…を追加」だけ置く |
| 絞り込みで0件 | Projects のページ | 絞り込みは残し、1行だけ出す。絞り込みはリンクなので、遷移した先でも外す手がページに残る |
| 保存完了 | 一覧・構成・見た目・サイト設定 | `?saved=1` を読んで帯を1回だけ。下書きの保存（`?saved=draft`）は「サイトにはまだ出ていません」まで言う |
| 置けないブロック | 構成 | 400。同じ種類を2つ置こうとしたとき、知らない種類のとき、動かす向きが不明なとき |
| 出せない中身 | ブロックフォーム | 400。中身が空・リンク集の落ちる行（「2 行目（Typo）の URL は…」「3 行目（No URL）に URL がありません」と名指し）は下書きでも止める（「公開」なのに出ない行を作らない）。見出しとひとことの一文の**長さも見る**——[下の表](#長さの上限)。**長さは下書きの保存では見ない** |
| 公開できない | 構成の「公開する」 | 303 でその行の編集画面へ。「公開できませんでした。下の理由を直して保存すると、公開されます」と、欄ごとの理由、「公開する」に印 |
| 重なった恒久リンク | Item フォーム・Member フォーム | 400。`slug` は1つの作品（人）を指すので、自動で `-2` を振らずに人に直してもらう。ほかの行の前の slug（転送に使っているもの）も使わせない（貼られた前の URL が行き先を変える） |
| slug を変えた | 一覧 | 「保存しました。前の URL は、新しい URL へ転送します」（`&moved=1`） |
| 二重送信 | 追加のフォーム | 同じ札で同じ中身の2度目は書かずに「保存しました」へ（1度目が書いている）。中身が違えば新しい札で書く |
| 読めない数 | Item フォーム・Member フォーム | 並び順が数でなければ 400（全角の数字は読む）。打った字をそのまま欄に返す |
| 消えた選択肢 | Item フォーム | 担当メンバー・プラットフォームが別のタブで消されていたら 400。「選び直してください」 |
| 並びに使われない年 | Item フォーム | 保存は通し、年の欄の下に注意の色で1行 |
| 代替テキストの無い画像 | Item フォーム | 公開の保存だけ 400。作品のページではその画像が作品の見た目を伝える唯一の手段。画像を選んで弾かれたときは「画像はまだ保存していません」と添える（ファイルの欄は描き直せない。Member フォームのアバターも同じ） |
| 受け取れない画像 | Item フォーム・Member フォーム | 400。中身が PNG・JPEG・WebP・AVIF・GIF のどれでもない（SVG・HEIC・名乗りと中身が違うもの）か、1MB を超える。下書きでも止める |
| 受け取れない URL | Item フォーム（リンク）・Member フォーム（GitHub） | 400。リンクは「2 行目の URL は…」「1 行目はラベルと URL の両方を…」と何行目かで言い、その行の欄に印。GitHub は `https://` から。公開ページでも同じ検査で落とす（保存と描画の2か所）ので、「保存できたのにサイトに出ない」行を作らない。下書きでも止める |
| 選べない見た目 | 見た目 | 400。帯を1本出し、保存はしない |
| 削除の確認 | 削除確認 | 対象名と、一緒に消えるものの件数。「非公開にする」逃げ道も添える |

### 長さの上限

残した上限は、名前と目録の文の長さだけ。どれも「1画面に収まるか」ではなく、その字が
出る場所の役目から決めている（`src/blocks.ts` の `MAX_CHARS` と `MAX_STATEMENT_SENTENCE`）。
**公開の保存でだけ**見る（下書きは長くても保存できる）。

| 書く場所 | 上限 | 理由 |
| --- | --- | --- |
| 作品名 | 32 字 | 一覧の行の題・作品のページの見出し・`<title>` と共有カードの題に出る名前 |
| 作品の説明文 | 100 字 | 目録の2文（「何であるか。何をしたか。」）。一覧の行は説明を切らずに全部出すので、長いと一覧が縦に伸びる |
| 個人ページの大見出し | 80 字 | 連動の大きな段で出る1つの文。長いと見出しがページの頭を何行も食う |
| ブロックの見出し | 10 字 | ひとことの一文を除く。目次の1行の名前で、上の帯に1行で並ぶ |
| ひとことの一文 | 120 字 | 大きく出る一文としての文言の決まり（超えると段落になる） |

上限は保存を押す前に見える（欄の hint と `maxlength`）。`maxlength` はブラウザ側の
目安で、保存してよいかを決めるのはいつもサーバー側の検査のほう。

以前は1画面に収めるための上限を持っていた——メモ 400 字・いま 250 字…（割ったあとの
1画面ぶんの字数）、紹介文 400 字・3段落、作品の本文 300 字・3段落、経歴は1画面 250 字、
作品のタグ3つ・リンク3本。どれも「節の弁が1pxも開かない最大」を測った数で、ページを
縦に読むようにしたので外した。

## 静的ファイル

Worker より先に配られる（`public/`）。

| パス | 中身 |
| --- | --- |
| `/app.css` | 全画面のスタイル。公開ページ・404 はこれだけを読む（`?v=` は中身の版。配り手は見ない） |
| `/admin.css` | 管理画面だけの規則。管理画面は `/app.css` のあとにこれを読む |
| `/preview.css` | 管理者専用プレビューの案内だけの規則。公開ページの `/app.css` と一緒に読む |
| `/assets/nebula-*.webp` | 星雲の透過素材6枚（iris・violet・ember・mint・sky・rose、1800×1000。mono は iris と共用）。`scripts/nebula/render.mjs` が形・色・4層の濃さから焼き、CSS が SHA-256 の頭8桁の版つき URL で読む。1年 immutable |
| `/assets/…` | favicon（`favicon.svg`・`favicon-32.png`・`apple-touch-icon.png`）、ブラックホールの光の絵（`blackhole.webp`。軌道図の真ん中とロゴの O。版つきの URL で1年 immutable）、ページの外で使う素材（ワードマーク `astlog-wordmark.svg`・GitHub の顔 `astlog-avatar.png`。顔は横から見たブラックホールの絵）、サイトの `og:image`（`astlog-avatar.png`。画像がある作品はその作品の画像）。作品・プロフィールの検査素材は本番には同梱せず、ローカル KV に入れる |

**ここに `robots.txt` や `sitemap.xml` を置かないこと。** どちらも Worker が
公開ページと同じ式から組み立てていて、`public/` に同じ名前のファイルを置いた瞬間に
静的なほうが勝ち、数え上げが静かに死ぬ。

公開ページが読み込む `<script src>` は0本。装飾開始の inline helper 1本だけを exact CSP hash で許す。
内容・絞り込み・ページの移動はサーバーと URL だけで成立する。
