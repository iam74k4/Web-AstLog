# 画面一覧

公開は6種類（トップの連なり・全体・メンバー個別の連なり・作品1件・機械に読ませる
2本・画像）で、画面の数は構成しだいに変わる。管理が 12 画面。ルートの実体は
`src/routes/public.tsx` と `src/routes/admin.tsx`。

## 公開側

誰でも見られる。出すのは `published = 1` の行だけ。骨格・色・書体は、管理の
[見た目](#見た目)で選んだものがそのまま全ページに効く。

公開ページは**1画面に1つぶんだけを収め、ページそのものはスクロールしない**。
入りきらないぶんは次の URL に送る。移動は普通のフルページ遷移で、JavaScript は
1バイトも持たない。縦に伸びてよいのは `/all` だけ。

表は `src/routes/public.tsx` の**登録順そのまま**。`/:screen` と `/:screen/:page`
は1語・2語の URL を何でも拾う catch-all なので、固定の URL は必ずその前に並ぶ。

| 画面 | パス | 出すもの | 中身が無いとき |
| --- | --- | --- | --- |
| 全体 | `GET /all` | 公開中のブロックを全部、1ページに縦に積んで | その節ごと出さない。見出しだけ残さない |
| トップ | `GET /` | 連なりの先頭の画面（ふつうは Hero）。先頭が1人のサイトのプロフィールなら、その1枚目へ 302 | 置いたものが全部空なら「まだ何も置いていません」 |
| メンバー個別 | `GET /members/:slug` | 名札（顔・名前・肩書きと所在地）と大見出しと、この人の一覧への帯（1人のサイトのプロフィールでは帯を出さない） | 下書き・不明な slug は 404 |
| メンバーの画面 | `GET /members/:slug/:screen` | `about` `skills` `career`（`contact` はサイトの `/contact` へ 301） | 書いていない画面は 404 |
| その画面の続き | `GET /members/:slug/:screen/:page` | 2画面目から（`/members/okazaki/career/2`） | 範囲の外は 404。`…/1` は `…` へ 303 |
| 作品1件（個人開発） | `GET /apps/item/:slug` | その作品だけの画面。頭に「← 一覧に戻る」（載っている Projects の画面へ）、底に作品同士をめくるページャ（`← 前` `Projects 3 / 7` `次 →`） | 下書き・不明な slug は 404 |
| 作品1件（業務） | `GET /works/item/:slug` | 同上（個人開発と業務は1つの列でめくる） | 1語目と種類が食い違う URL も 404 |
| 以前の一覧 | `GET /apps` `/apps/:page` `/works` `/works/:page` | 同じ区分で絞った `/projects` へ 301（`?member=` は引き継ぐ） | — |
| クローラへの指示 | `GET /robots.txt` | `text/plain`。`/admin/` だけ外す | — |
| URL の一覧 | `GET /sitemap.xml` | `application/xml`。公開中の画面を数え上げる | — |
| 画像 | `GET /images/avatars/…`<br>`GET /images/items/…` | KV に入れたアバターと作品の画像。キーの形（置き場 / 英数字で始まり英数字と `. _ -` だけの名前）に合わないものは読みに行かない（KV のキーを外に開く口なので、置き場の外は読ませない）。どの応答にも `X-Content-Type-Options: nosniff` と `Content-Security-Policy: default-src 'none'; sandbox`（同じオリジンで配るので、画像のふりをした文書が直に開かれても走らせない）。content-type は KV に入れた型が5種類（PNG・JPEG・WebP・AVIF・GIF）のどれかならそのまま、それ以外（以前の SVG・HEIC）は `application/octet-stream` の添付（`Content-Disposition: attachment`） | 該当なし・形が合わないものは 404 |
| 画面 | `GET /:screen` | そのブロックの1画面目（`/projects` `/team` …）。1人のサイトの `/team` はプロフィールの1枚目へ 301 | 無い画面名は 404 |
| 画面の続き | `GET /:screen/:page` | 2画面目から（`/projects/2`）。1人のサイトの `/team/:page` もプロフィールの1枚目へ 301 | 範囲の外は 404。`/projects/1` は `/projects` へ 303 |

作品の恒久リンクが3語なのは、catch-all（1語・2語）と取り合わないようにするため。
2語（`/apps/<slug>`）にすると、めくる先の番号と作品の名前が同じ位置で取り合い、
slug が数字の作品を作れなくなる。一覧を Projects の1つにまとめたあとも、恒久リンクは
区分の語（`apps` / `works`）のまま変えていない——貼られた URL を動かさないため。

404（未定義の URL）と 500（例外）は、ルートではなく `src/index.tsx` の
`notFound` / `onError` が受ける。マークと戻り導線だけを出す。説明は訪問者の
言葉で書く（404 は「URL が変わったか、打ち間違えているかもしれません。」）——
`slug` のような管理画面の言葉は、ここに着いた人には読めない。

登録順は散文だけでなくテストが守っている（`test/public.test.ts` の「URL の登録順」が
Hono の `publicRoutes.routes` を読み、catch-all が最後の2本だけであることを見る）。

絞り込みは query で足す。どの画面にも付けられる。

| query | 効く先 | 例 |
| --- | --- | --- |
| `?kind=app\|work` | Projects（個人開発 / 業務） | `/projects?kind=work` |
| `?member=<slug>` | Projects | `/projects?member=okazaki` |

知らない区分・公開中に居ない slug は、絞り込みとして扱わず全件を出す。ピルに
並ばないもので絞り込むと、外す手が画面から無くなるため。同じ理由で、区分のピルが
並ばないサイト（項目が片方の区分にしか無い）では `?kind=` を、公開中が1人の
サイトでは `?member=` を読まない（名前のピルは2人以上いるときだけ並ぶ）。
一覧を持たない画面（Team など）には絞り込みを付けて回らない。絞り込みはページャにも
目次にも同じものが付いて画面をまたいで効き、canonical には付けない
（同じ中身の取り出し方なので、組み合わせのぶんだけ URL を数えさせない）。

`all` は画面の名前としての予約語。決まった中身のブロックの key
（`hero` `apps` `works` `team` `contact`）とも、打ち込むブロックの `block-<id>`
とも衝突しない。**固定のルートは `/:screen` より前に登録する。** あとから下に
足すと、一致が catch-all に吸われて、そのページだけが静かに 404 になる。

先頭の画面は `/` と `/<slug>`（`/hero`）の2つで開ける。canonical は `/` に
そろえ、2つ目からはその画面の URL が正。題も説明文も画面ごとに変える（同じ題の URL が
並ぶと、履歴から選び直せない）。**構造化データ（JSON-LD）は連なりの先頭の画面にだけ
載せる**——同じ名乗りが画面の数だけ並ぶと、どれが本体か決められない。1人のサイトの
プロフィールの画面は連なりの途中なので載らない（先頭に置いた構成でだけ、その1枚目が
名乗る）。

**柱は入口の外で名乗る。** 1人のサイトなら、入口（Hero の画面）以外のどの画面
（Projects・個人ページ・作品・Contact・`/all`）でも、柱に名前と職種を出す。入口では
Hero の `h1` と肩書きが名乗るので、柱は黙る（同じ名前を2度並べない）。899 以下の帯には
ロゴの印・名前・目次が入り、ワードマークと職種は畳む（ワードマークは見た目だけ。ロゴの
リンクの読み上げには残る）。2人以上のサイトでは柱に名前を出さない。Contact の画面では
柱の GitHub / Mail を出さない（本文のボタンと同じ行き先が2組並ぶ）。

`<meta name="description">` と `og:description` は、**その画面に実際に出ている文字**
から作る（`src/routes/public.tsx` の `DESCRIPTION_MAX` は 110 字。超えたら末尾を `…`
にして切る）。入口＝名乗り、Projects＝件数と区分とその画面のカード名（業務は
実績値も）、Team＝名前と職種、個人ページ＝その画面の中身（1枚目は大見出し）、
打ち込んだブロック＝見出しとその画面の行、
`/all`＝実際に描いた節の名前。固定の文を書かないのは、中身を足した日に説明文だけ
古くなるため。

Contact は画面に出ている誘いの1文（`src/site.ts` の `contactLead`）をそのまま使う。
ボタンの字（「メールを送る・GitHub」）だけでは、検索結果でも貼られたカードでも
何のための画面か分からない。

共有カードの画像（`og:image`）は、作品のページで画像があればその作品の画像
（絶対 URL。種類は経路の拡張子から、寸法は上げたときに読んだ `items.image_width` /
`image_height`。分からないものは名乗らない。AVIF は貼り先が読まないのでサイトの1枚に
戻す）、それ以外はサイトの1枚（`/assets/avatar.png`、144x144 PNG）。`twitter:card` は
画像の寸法で決め、横長で 300x157 以上なら `summary_large_image`、それ以外（サイトの1枚・
縦長・寸法が分からない）は `summary`。サイトの1枚は推奨の 1200x630 に届かないので、
貼り先は小さな正方形のサムネイルを出す。**足りないもの: 1200x630 の PNG 1枚**——置いたら
`src/ui/Layout.tsx` の `SITE_IMAGE` を差し替えるだけでよい（札は寸法から決まる）。

### 機械に読ませる2本

`/robots.txt` は `User-agent: *` / `Allow: /` / `Disallow: /admin/` と、絶対 URL の
`Sitemap:` 行。相対では書けない（クローラが読まない）。

`/sitemap.xml` は手で並べた表を持たず、公開ページと同じ式から数え上げる——
トップの画面（`siteSteps` の canonical。1人のサイトではプロフィールの画面もここに入り、
`/team` は入らない）／全体ページ `/all`／個人ページ（`memberScreens`。割った2画面目も
出る）／作品の恒久リンク（`itemHref`）の4つ。入口 `/` は、連なりの先頭がプロフィールの
構成（そこへ 302 で送るだけ）でだけ載せない。
載らないのは下書き・0件で消えた節・絞り込み付きの URL・`/admin`。同じ URL は1度だけ。
**新しい連なりを足したら、この4行にも1行足すこと。**

どちらも Worker のルートで返す。`public/robots.txt` や `public/sitemap.xml` を
置いてはいけない——`public/` は Worker より先に配られるので、置いた瞬間に静的な
ほうが勝ち、数え上げが静かに死ぬ。

### トップの構成

トップは「決まった部品（ブロック）の連なり」で、管理の[構成](#構成)から
置く・外す・前後に動かす。部品の見た目は変えられないので、どう並べても同じ設計の
中に収まる。何も置いていなければ Hero → Projects → Team → Contact の順。

1つのブロックは**件数しだいで何画面にもなる**。1画面あたりの件数（`perScreen`）と
字数（`maxChars`）は `src/blocks.ts` が正で、割るのは `src/lib/paginate.ts`。CSS の
値ではなく件数なので `:root` には置かない。管理画面からも変えられない（見た目を
変える口にしないため）。Projects の**列の数**もここから出る——`perScreen` を
`style="--cols:2"` でそのまま渡すので、1画面ぶんが必ず1行に並ぶ（600 未満は1列）。

| ブロック | 中身 | 出す条件 | 1画面あたり | 備考 |
| --- | --- | --- | --- | --- |
| Hero | 名乗り（1人なら名前と肩書き、それ以外はサイト名）とリード（`src/site.ts`） | 常に | 画面まるごと | 目次には載らない。標語は置かない。月を右上に、字を画面の下に寄せる。リードの下に一覧への帯（丸い札。題は「つくったもの」、右端に「一覧で見る →」）、その下に全体ページへの控えめな1本「すべてを1ページで読む →」。帯の行き先がページャの「次」と同じ（既定の並び）なら、入口にはページャを出さない |
| Projects | 公開中の項目（個人開発と業務を混ぜて） | 1件以上 | 2 件 | 新しい順（年の頭の4桁 → 管理画面の並び順。「2024 — 現在」は 2024）。絞り込みピルは「すべて / 個人開発 / 業務」で、区分のピルは両方の区分に項目があるときだけ並ぶ。見出しの添えは、ピルが並ばない（区分が1つの）ときだけその区分名。業務の実績値は1項目に1つだけ。以前の Apps と Works をまとめたもの。画像のある作品は **600 以上で**カードの頭にサムネイル（3:1 の枠、`--thumb-ratio`。雑誌風は 4:1）。同じ行に画像の無い作品が混ざったら、そちらにも空の枠を置いて題をそろえる。行に1枚も無ければ枠は出さない。説明は 600 以上で6行（上限の 100 字が切れずに出る）、600 未満は2行で止める。画像の枠のある行だけ 900 以上で3行 |
| Team | 公開中のメンバー | 2人以上（1人ならプロフィールに置き換わる） | 6 人 | 見出しに添えは無い（「メンバー」は訳語でしかない）。カードの押す手は「プロフィール →」。**2人は横長カード、3人以上はグリッド**。人数で決める、画面幅では決めない。公開中が1人なら Team の画面は作らず、その位置にその人の画面（1枚目・About・Skills・Career）が並ぶ（目次は「Profile」の1行）。`/all` では Profile の節になる |
| Contact | 連絡先（`src/site.ts`） | 常に | 画面まるごと | 連なりの締め。画面に出すのは月と、誘いの1文（`contactLead`）と、ボタン2つ（メール・GitHub）。見出しは読み上げ用の `.sr-only` の h1。月は右上、入口の三日月を左右に返して小さく置く（動かさない）。1文とボタンは画面の下。`/all` ではほかの節と同じ見出しと、同じ1文と、アドレスの字を置く（印刷の宛先）。GitHub のプロフィールもここに常設 |
| ひとこと | 大きな一文と添え書き（段落は何段でも） | 一文がある | 300 字 | 目次には載らない。一文はその画面の `h1` |
| いま | 「何を \| 補足」の箇条書き | 1行以上 | 10 件 / 250 字 | |
| 数字 | 「値 \| 単位 \| 説明」のタイル | 1行以上 | 6 件 / 160 字 | 2〜4つが収まりがよい |
| リンク集 | 「ラベル \| URL \| 補足」 | 有効な URL が1行以上 | 10 件 / 160 字 | `https://` `mailto:` `/` 以外は落とす。`//host` は外部 URL なので通さない。URL は字数に数えない |
| できごと | 「年月 \| 何を \| 補足」 | 1行以上 | 5 件 / 250 字 | 個人ページの経歴と同じ形 |
| メモ | 段落の文章 | 1段落以上 | 3 段落 / 400 字 | 見出しは無くてもよい。無ければ目次にも載らない |

上の4つは1つずつしか置けない。下の6つはいくつでも置ける。

目次は、実際に出た節だけを、出た順に載せる（まとめる単位は `src/lib/sequence.ts` の
`tocKey`。ふつうは節と同じで、1人のサイトのプロフィールだけは4つの節を「Profile」の
1行にまとめる）。**番号（01〜）は振らない**——目次の番号は
ブロックの並び順なので `/projects` でも `/projects/3` でも動かず、画面の底のページャが出す数と
2組並ぶと、同じ数え上げに見える。数えるのはページャ1つに寄せる。
ブロックの2画面目以降を見ているあいだも、その見出しに印（`aria-current="page"`）が残る。

**ページャが数えるのは節の中**（`Projects  2 / 4`）で、サイト全体の通し番号ではない。
全体で数えていたころ（`01 · 07`）は3つ困っていた——柱の「Apps」を押しても Apps が
3画面あることがどこにも出ない、「次 →」が節の中の移動と節をまたぐ移動を兼ねていて
`/apps/3` で押すと予告なく Works に出る、そして**絞り込みが無関係な画面の番号を動かす**
（Apps を macOS で絞ると 3画面が1画面になり、`/contact` の番号が `07` から `05` へ。
実測で、`/contact` と `/contact?platform=macos` の違いはその数字だけだった。
いまの Apps / Works は Projects の1つにまとまっている）。

めくる先は今までどおり連なり全体なので、「次」を押し続ければサイトを一周できる。
変わったのは数え方と、**節をまたぐときに行き先を名乗る**こと（`← 前` が
`← Projects` になる）。名前を持たない節（Hero・ひとこと）は1枚しか無いので数を出さない。

**入口では、帯とページャの「次」が同じ行き先ならページャを出さない。** 既定の並び
（入口 → Projects …）では、同じ `/projects` へのリンクが画面の中ほどの帯と底の
「次 →」に2つ並んでいた。件数を添えて何があるかを見せる帯のほうを残す。入口が
連なりの先頭でない（前に画面がある）ときと、行き先が違う（入口と Projects の間に
ひとことを置いた）ときは、今までどおり出す。

「画面まるごと」のブロックに2画面目は無い。1つの段落や1つの文はどこにも割れない
ので、そちらは長さの上限で受ける（[出せない中身](#画面の状態)）。

節そのものが弁（`overflow: auto`）なので、割られた画面の節には `tabindex="0"` が
付き、見出しを持つものは `role="region"` と見出しと同じ `aria-label` を持つ。
`main` の直接の子になる箱は `src/ui/components.tsx` の `Screen` / `Hero` だけが作る。
フォーカスの輪郭は節の縁の内側に描く（外へ離すと柱の帯やページャの罫線と並んで
見分けにくい）。

**割られた画面の節は上揃え。** 見出しはどの画面でも同じ高さから始まり、めくっても
跳ねない（空きは中身の下、ページャの上に集まる）。上下中央に寄せていたころは
`/projects` 91px → `/projects/2` 124px → `/projects/4` 243px と跳ねていた
（rail @390x844）。上揃えにしないのは Hero（入口は字を画面の下、個人ページの1枚目は
中央）と Contact（字とボタンを画面の下）だけ。`npm run check:fit` が、同じ骨格・寸法の
中で見出しの上端がそろっていることを測る（作品のページは見出しの上の「← 一覧に戻る」の
上端）。

### 全体ページ

`GET /all` は、公開中のブロックを全部1ページに縦に積んで出す。画面ごとに割らず、
一覧も全件を出す（`perScreen` を使わない唯一の公開ページ）。**canonical は自分自身**。
節は `#projects` のような id で並ぶので、画面ごとの URL（`/projects`）と同じ節をアンカーでも
指せる。この1本が受け持つのは次の役目。

- 印刷。1回で全部が紙に載る
- Ctrl-F とブラウザ翻訳。ページをまたがずに全文を探せる・訳せる
- オーナーが全体を通しで点検する
- 画面ごとの組み立てが効かない環境での退避先

canonical を `/` にしていたころは、中身が全部ある唯一のページを「作品を1件も
含まないトップの複製」として申告していた——index に載るのが中身の薄い準重複の
画面ばかりで、完全版が載らない、という逆の形になる。画面ごとの URL はそれぞれ
自分を正と名乗り、`/all` も自分を名乗る。

縦に伸びてよい唯一の公開ページなので、画面に収める外枠はここには当てない
（目印は `body[data-whole]`）。弁が無く、ページ自身が動くので、節に `tabindex` も
付けない。

1人のサイトでは、Team の節の代わりに **Profile の節**（`#profile`、目次も「Profile」）を
置く。中身はその人の名札・大見出し（大きな一文）・紹介・技術・経歴で、画面ごとの URL
では4〜N枚に割れているものを1つの節に積んだもの。見出しの段は Hero の `h1` →
Profile の `h2` → About / Skills / Career の `h3` → 技術の小見出しの `h4`。中身の無い
小節は見出しごと出さない（割られた画面の About は空でも「準備中です」を出すが、あれは
URL を間違えたのかを見分けるため）。部品は割られた画面と同じもの
（`src/ui/components.tsx` の `ProfileWhole`）。

行く道は3本ある。公開側は柱の足元の「全体を1ページで見る →」と、入口の帯の下の
「すべてを1ページで読む →」（`WholeLink`）、管理側は「構成」のヘッダの
「全体を1ページで見る ↗」。足元の1本は 899 以下では畳まれる（`.rail__footer` ごと）
ので、スマホの幅では入口の1本が受ける（こちらは幅で畳まない）。中央寄せの骨格の
900 以上では柱が上の帯になり、足元の著作権表示は出さずに、全体ページへの1本だけを
目次と同じ行に置く。`sitemap.xml` にも載るので検索からも届く。

### メンバー個別ページ

個人ページもトップと同じ規則の連なりで、1画面 = 1ドキュメント。件数の軸も同じ形で
持つ（`src/blocks.ts` の `MEMBER_PER_SCREEN`。割るのは同じ `src/lib/paginate.ts`）。

**個人ページはサイトの連なりの一部。** 柱と目次はサイトのままで、個人ページ専用の
ものに入れ替えない。以前は柱（顔・名前・所在地）も目次（About / Skills / Career /
Contact / Apps · Works）も個人ページ専用のものに丸ごと入れ替わり、Team のカードを
押すと別のサイトへ飛んだように見えた。1枚目には「←」が無く、Team へ戻る道はロゴ
（入口まで戻る）しか無かった。連なり方は人数で2つに分かれる。

**1人のサイト（Team を置いているとき）: プロフィールがサイトの連なりそのもの。**
Team の画面は作らず、その位置にこの人の画面が並ぶ。`/` から「次」を押し続けると一周する。

```
入口 ──▶ Projects … ──岡崎 昂功 →──▶ 1枚目 ──▶ About ──▶ Skills ──▶ Career ──Contact →──▶ Contact
                       目次ではこの4つが「Profile」の1行（どの画面でもそこに印）
```

1枚の細いカードだけの Team の画面は、複数いる前提の器に1人しか入っていないことを
画面1枚ぶん使って告知していた。中身はカードを押した先のほうにあるので、Team の位置に
中身そのものを置く。`/team` と `/team/<n>` は1枚目へ 301（2人目を公開すると Team の
画面に戻る。301 はブラウザに覚えられるので、一度寄せられた人はしばらくプロフィールへ
運ばれる）。1枚目の帯（このメンバーのつくったもの）は出さない——入口の帯と同じ行き先・
同じ件数の札が、連なりに2度出る。構造化データも載せない（連なりの途中。先頭の入口が
同じ人を名乗っている）。

**2人以上のサイト: Team の続き。** 目次はサイトのまま（Team に印）で、ページャはサイトの
列の Team の直後にこの人の画面を差し込んだ列でめくる。

```
Team ──カード──▶ 1枚目 ──▶ About ──▶ Skills ──▶ Career ──▶ Contact（サイトの締め）
  ◀── ← Team ───┘                                  └── Contact → ──▶
```

Team を置いていないサイトでは、差し込む先が無いので、この人の画面だけの単独の連なり
（カードの担当者名から入る。1人のサイトでもこちら）。

| パス | 出すもの | 出す条件 | 1画面あたり |
| --- | --- | --- | --- |
| `/members/<slug>` | 名札（顔・名前・肩書きと所在地）と大見出しと、この人の一覧への帯（1人のサイトのプロフィールでは帯無し） | 常に | 画面まるごと |
| `/members/<slug>/about` | 紹介文 | 常に。空なら「準備中です」 | 3 段落 |
| `/members/<slug>/skills` | 技術。塊の中は経験の添えごとの行（添えは行の頭に1度だけ、`dt` / `dd` の組。添えの無い項目は最後の行） | 書いてあるときだけ | 3 塊 |
| `/members/<slug>/career` | 経歴 | 書いてあるときだけ | 5 行 |

割れた2画面目からは `/members/<slug>/<screen>/<page>`（例
`/members/okazaki/career/2`）。1画面目は `…/<screen>` ひとつに寄せてあり、`…/1` は
そこへ 303。`/01` や `/abc` は 404。文法はトップの `/:screen/:page` と同じで、
読み方も同じ関数（`readPage`）が持つ。

数はどれも発明ではなく導出してある。About は書く側の上限
（`MAX_CHARS.memberBioParagraphs` = 3。「3段落・400 字なら弁が1pxも開かない」という
実測そのもの）、Career は同じ `<Timeline>` と `.career` で描く「できごと」ブロックの
`perScreen`。Skills の 3 だけは 27通りの実測ではなく、app.css が「技術の3つの塊」と
呼んでいる今日の姿に合わせた保守的な数。**`skillsText` と `careerText` には字数の
上限がまだ無い**——1つの塊・1行が極端に長い場合だけが残った穴で、数を決めるには
骨格3 × 書体3 × 設計サイズ3 の実測が要る。

- 書いていない画面は作らない。URL も目次もページャも一度に消える（404）。
  技術も経歴も書いていない人は3画面。**5枚固定ではない**——紹介7段落・技術4塊・
  経歴6行のような中身では6枚以上になる
- About を空でも残すのは、まだ書いていないのか URL を間違えたのかを、読み手が
  見分けられるようにするため
- 入口は `/members/<slug>` ひとつ。1枚目に2つ目の URL（`…/hero`）は作らない
- 作品のカードはここに複製しない。1枚目の帯から `/projects?member=<slug>` へ送り、
  一覧をその人で絞り込んだ1画面目に着かせる。帯の件数は区分ごと（`個人開発 2 · 業務 1`）
  で、その人に項目の無い区分は数えない。どちらも0件か、トップに Projects を置いて
  いなければ帯ごと出さない。1人のサイトでは `?member=` を付けない（Team を置いて
  プロフィールになっているときは帯そのものを出さない）
- 目次は、2人以上のサイトではサイトのもの（Projects / Team / Contact）で、印は Team に
  付く（作品1件のページが、載っている一覧に印を付けるのと同じ借り方）。1人のサイトでは
  Projects / Profile / Contact で、印は Profile。About / Skills / Career はページャで
  めくる。ページャは節をまたぐ手だけ行き先を名乗る——1枚目の「← Team」（1人のサイトでは
  「← Projects」など手前の節）、About の「← 岡崎 昂功」、最後の画面の「Contact →」
- 2人以上のサイトでは、Team の画面自身の「次」は変えない（Contact のまま）。個人
  ページはカードから入る脇の道で、何人いても Team の次は Contact
- 顔は1枚目の名札（`.nameplate`）にだけ出る。Team のカードと同じ並びで、押した先で
  同じ顔に着く。名前は、1人のサイトなら柱にも出る。`h1` は大見出し
  （`<h1 class="hero__headline">`）、大見出しを書いていない人では名札の名前
  （`<h1 class="nameplate__name">`）
- 連絡先はサイトの Contact に合流させた。`/members/<slug>/contact` はそこへ 301
  （サイトに Contact が無ければ 404）。サイトと違う GitHub / メールを持つ人だけ、
  1枚目にその行き先を置く（同じ行き先を2つ置かない）
- 構造化データは `Person`（1枚目にだけ）。公開中が1人のあいだは `worksFor` を出さない
  ——トップが同じ URL を `Person` として名乗っているので、書くと1つの URL が2つの型を
  持つ。1人のサイトで Team を置いているときは、個人ページが連なりの途中なので載せない

### 作品1件のページ

`GET /apps/item/<slug>`（個人開発）と `GET /works/item/<slug>`（業務）。一覧の URL（`/projects/3`）は
「いまの並びの3枚目」でしかなく、並べ替え・公開の切り替え・追加のたびに 200 の
まま別の作品を指す。貼れる URL はこちら。

- 出る条件は「その作品が公開中」の1つだけ。**トップの構成には依らない**——Projects の
  節を外しても、貼られた作品のリンクは死なない
- 下書きは 404。1語目と種類が食い違う URL（`/works/item/<app の slug>`）も 404
  （同じ作品に2つの URL を作らない）
- **作品同士をめくる列**を持つ。並びは一覧と同じ（新しい順。区分をまたぐ）で、
  恒久リンクを持つ作品だけ。ページャは `← 前` / `Projects 3 / 7` / `次 →` で、
  端ではリンクを出さない（1件しか無ければページャごと出さない）。読み上げでは
  「Projects の 7 件のうち 3 件目」——単位は画面ではなく件（`ScreenPager` の `unit`）。
  サイトの連なり（Hero → … → Contact）とは継がない。継ぐと最初の作品の「←」が
  Contact を指す
- 本文の頭に「← 一覧に戻る」（`BackLink`）。行き先は**その作品が載っている** Projects の
  画面で、一覧の並びの中の位置を `perScreen` で割って出す（1画面目なら `/projects`、
  ほかは `/projects/N`。`slug` の無い作品も一覧には載るので数に入れる）。Projects を
  先頭に置いた構成では1画面目が `/`、Projects を置いていない構成では出さない
- 目次はトップと同じ画面の列を出し、印はその作品が載っている一覧（Projects）に付く。
  作品の列は目次に並ばない
- 見出しの下は**カードを開いたもの**（`ItemDetail`）。説明・実績値（`Metric`）・タグ・
  行き先（`LinkRow`）はカードと同じ部品で、行止め（`--card-lines`）を外した全文。
  足すのは画像（`Shot`）と本文（`items.body`）だけ。説明と本文は1つの段落の列
  （説明が頭の1段落）。実績値を「数字」の箱、行き先をリンク集の行で出していた
  ころは、説明 100 字・実績値・行き先3本の作品に画像を置くと、本文が無くても弁が
  開いた
- 画像は `figure`（代替テキストは管理画面で書いた `image_alt`）。枠の高さは `--shot-h`
  で、絵は `object-fit: contain` で切らずに縮める。900 未満は見出しのすぐ下、900 以上
  は文の列を左・画像を右に並べ（`.detail--shot`）、枠は文の列と同じ高さまで伸びる
- 本文と画像は作品のページにだけ出る（カードのサムネイルは同じ画像の飾りで、
  `alt=""`）。無ければ `figure` も本文も出さない
- 足した見た目は「← 一覧に戻る」の札（`.back`。ページャの手と同じ丸い札、当たり判定は
  `--tap`）と、画像の枠（`.shot`）と、列の組み方（`.detail`）
- 構造化データは `CreativeWork`（name / url / description、画像があれば image を
  絶対 URL で）。名乗りではないので、めくった先の作品にも載る（名乗りは連なりの
  先頭だけ）。description（`<meta>` も）は説明（summary）のまま。`<title>` と
  `og:title` は「&lt;作品名&gt; — Noctifex」、canonical と `og:url` は自分の URL。
  `og:image` は画像があればその作品の画像（上の「共有カード」の段落）
- 行き先（`LinkRow`）は部品の中で `isSafeUrl` を通し、通らない行（`javascript:`・
  頭を省いた相対 URL）は描かない。全部落ちたら行ごと出さない。保存でも弾いているが、
  その検査より前に入った行を呼ぶ側に頼らずに落とす
- 一覧のカードは**面ごと**この URL へのリンク（`/all` のカードも同じ）。リンクは題の
  1本（`.card__link`）で、その `::after` がカードを覆う。カードの中の Repository と
  担当者名は覆いの上に出ていて、それぞれの行き先へ行く。`slug` の無い作品は素の題の
  まま——押せる面にもならず、ホバーでも浮かない（当てにならない URL を出すくらいなら
  出さない）
- 「担当」（個人ページへのリンク）は、カードの担当者名と同じ条件で出す。2人以上
  いるとき、または Team の節を置いていないとき（そうしないと個人ページへの道が
  トップから1本も無くなる）。行き先の1行（`LinkRow`）に「担当 &lt;名前&gt;」として並び、
  サイトの中の行き先なので矢印は `→`・同じタブ（`↗` は外へ出る・別タブの印だけ）

## 管理側

`/admin/*`。ログインが要る。ログインは GitHub / Google の OAuth だけで、パスワードは
無い。書き込み（POST）は送り元も確かめる——Origin → Sec-Fetch-Site → Referer の順に
見て、origin が違えば 403（`Origin: null` も 403）。壁の外のログアウトも対象。

公開ページからは、**ログインしているあいだだけ**柱に「管理画面」が出て、いま見ている
画面を直す場所へ同じタブで送る（行き先の表は [flow.md](./flow.md#公開側)）。訪問者には
出ない。出したページは `cache-control: private, no-store` で返す。

| 画面 | パス | 認証 | 役割 |
| --- | --- | --- | --- |
| 入口 | `GET /admin` | 要 | `/admin/members` へ 303 |
| ログイン | `GET /admin/login` | 不要 | 「GitHub でログイン」「Google でログイン」の2つの**リンク**（フォームではない。ID とシークレットがそろった提供元だけ）。`?next=` はリンクの query に持ち回す。`?error=`（`denied` / `expired` / `provider`）と `?out=all` は帯を1本 |
| ログイン開始 | `GET /admin/auth/:provider/start` | 不要 | `provider` は `github` / `google`（ほかは 404、未設定なら 503）。D1 の `oauth_states` に state・PKCE の verifier・nonce・安全化した `next` を1行（10分）、同じ state をクッキー（`Path=/admin/auth`・`SameSite=Lax`）に置き、提供元へ 302。コールバックはリクエストの origin（開発では `.dev.vars` の `OAUTH_REDIRECT_ORIGIN`）＋ `/admin/auth/:provider/callback`。期限切れの行はここで掃除する |
| ログインの戻り | `GET /admin/auth/:provider/callback` | 不要 | クッキーと query の state の札を**先に消してから**照合。食い違い・クッキー無し・再利用・期限切れ・提供元の違いは `/admin/login?error=expired`、提供元で断ったら `?error=denied`（どちらも `next` を持ち回す）。成功で前のセッションを捨てて Cookie を発行し、`next` の画面（`/admin/` の中だけ）か `/admin` へ 303。紐づいていないアカウントは 403、提供元との通信の失敗は 502、Google の id_token が合わないものは 400 |
| ログアウト | `POST /admin/logout` | 要 | セッションを消す |
| アカウント | `GET /admin/account` | 要 | 紐づいたアカウント（提供元・@ログイン名かメールアドレス・最後のログイン〔日本時間〕）と「すべての端末からログアウト」。左ナビの足元の名前から入る。紐づけ・外しはここではしない |
| すべての端末からログアウト | `POST /admin/account/logout-all` | 要 | その人のセッションを、いまの端末のものも含めて全部消し、`/admin/login?out=all` へ |
| Members 一覧 | `GET /admin/members` | 要 | 行に 公開/下書き・並び順・編集・削除。公開中の行には「サイトで見る ↗」 |
| Member フォーム | `GET /admin/members/new`<br>`GET /admin/members/:id/edit` | 要 | 追加と編集で同じテンプレート |
| Member 保存 | `POST /admin/members`<br>`POST /admin/members/:id` | 要 | multipart。アバターは作品の画像と同じ検査（中身の先頭のバイトで PNG・JPEG・WebP・AVIF・GIF だけ、1MB まで）で KV の `avatars/` へ。GitHub は `https://` の絶対 URL だけ（欄も `type=url`。下書きでも見る）。検査が全部通ってから KV に置き、D1 が落ちたら置いた画像を消す。差し替えで使われなくなった画像は D1 のあとで消す。成功で `?saved=1`（下書きなら `?saved=draft`）を付けて一覧へ |
| Member 削除 | `GET /admin/members/:id/delete`（確認）<br>`POST` 同 URL（実行） | 要 | 確認画面を必ず挟む。キャンセルは来た画面へ（編集から来たら `?from=edit` で編集へ） |
| Items 一覧（Projects） | `GET /admin/items?type=app\|work` | 要 | 個人開発 / 業務をタブで切り替え（公開ページでは Projects の1つの一覧にまとまる）。行に恒久リンクの URL（無ければ「恒久リンクなし」） |
| Item フォーム | `GET /admin/items/new?type=…`<br>`GET /admin/items/:id/edit` | 要 | `type` で欄が変わる（個人開発はプラットフォーム、業務は業界と実績値）。恒久リンクの `slug` もここ。本文・画像（ファイル）・画像の代替テキストはどちらの区分にもある。年・説明・本文・実績値の添えには書き方のヒントを出す（続いているものは「2024 — 現在」、説明は常体・本文は「です・ます」、添えは値と単位のあとに続けて読まれる）。画像がある作品には、いまの画像の見本（作品のページと同じ枠）と「画像を外す」 |
| Item 保存 | `POST /admin/items`<br>`POST /admin/items/:id` | 要 | multipart。タグとリンクは総入れ替え。リンクは1行ずつ見て、URL が `isSafeUrl` を通らない行・ラベルか URL の片方しか無い行は 400 で何行目かを示す（下書きでも見る。両方空の行は数えない）。`slug` の重なりは 400 で戻す。画像はアバターと同じ検査（中身の先頭のバイトで5種類だけ、1MB まで）で KV の `items/` へ。拡張子と content-type と寸法は判定の結果から付ける（名乗りは使わない）。画像の URL はフォームから受け取らない。検査が全部通ってから KV に置き、D1 が落ちたら置いた画像を消す。差し替え・「画像を外す」で使われなくなった画像は D1 のあとで KV から消す。**公開の保存では**説明・本文の長さと、画像があるときの代替テキストを見る（下書きでは見ない）。止める理由は全部まとめて返す。成功で `?saved=1`（下書きなら `?saved=draft`） |
| Item 削除 | `GET /admin/items/:id/delete`（確認）<br>`POST` 同 URL（実行） | 要 | 一緒に消えるタグ・リンクの件数（画像があれば画像も）を出す。画像は KV からも消す。キャンセルは Member と同じく来た画面へ |
| 構成 | `GET /admin/blocks` | 要 | 公開ページの画面の連なり。行ごとに ↑↓・公開/下書き・編集・外す・**「N 画面」**。頭に合計。ヘッダに「サイトを見る ↗」と「全体を1ページで見る ↗」。下に「足す」のカタログ |
| ブロック追加 | `POST /admin/blocks`（決まった中身のもの）<br>`GET /admin/blocks/new?type=…` → `POST /admin/blocks`（打ち込むもの） | 要 | Contact の手前に足され、その行（`#block-<id>`）へ戻る。打ち込むものは下書きから始まる |
| ブロックフォーム | `GET /admin/blocks/:id/edit`<br>`POST /admin/blocks/:id` | 要 | 決まった中身のものは「公開する」だけ |
| ブロック公開切替 | `POST /admin/blocks/:id/publish` | 要 | 一覧の行から公開／下書きを直接切り替える。中身は触らない |
| ブロック移動 | `POST /admin/blocks/:id/move`（`dir=up\|down`） | 要 | 並び順を 10 刻みで振り直し、動かした行（`#block-<id>`）へ戻る |
| 既定の並び | `POST /admin/blocks/init` | 要 | 何も置いていないときだけ5つを入れる |
| ブロック削除 | `GET /admin/blocks/:id/delete`（確認）<br>`POST` 同 URL（実行） | 要 | 決まった中身のものは、外しても登録した項目は消えない |
| 見た目 | `GET /admin/appearance`<br>`POST` 同 URL（保存） | 要 | 骨格・アクセント色・書体を選ぶ。サイト全体に効く |

どの画面も、左ナビの足元の「サイトを見る ↗」から公開ページを別タブで開ける。
その下の名前（最後にログインしたアカウントの @ログイン名かメールアドレス）は
アカウントの画面への入口。

以前の初期設定（`/admin/setup`）とパスワードのログイン（`POST /admin/login`）は無い。
`/admin/setup` は GET も POST も 404、`POST /admin/login` は壁に当たってログイン画面へ
303 で戻る（セッションはできない）。最初の owner は、`wrangler.toml` の
`OWNER_GITHUB_ID` / `OWNER_GOOGLE_EMAIL` と一致するアカウントの初めてのログインで紐づく。

一覧・フォーム・確認の3種類だけで、Members・Items・構成をまかなっている。
一覧にフォームを同居させないのは、「どの行を編集中か」が読めなくなるため。
見た目だけは一覧を持たない。選ぶものが3つで、増えも減りもしないため。

### 構成

公開ページの画面の連なり。行の ↑↓（読み上げは「前へ / 後ろへ」）はそれぞれ
小さな `POST` フォームで、押すと 303 で同じ一覧に戻る（JavaScript は使わない）。

- 行ごとに「**N 画面**」、一覧の頭に「合計 N 画面」を出す。**読み取り専用の
  知らせで、ここから件数は変えられない**。数え方は公開ページと同じ
  （`src/blocks.ts` の `perScreen` と `src/lib/paginate.ts`。中身を単位に開く式も
  `blockLines` / `blockTexts` / `blockUnitCount` の1本を公開側と共有する）。下書きと、
  中身が0件のものは 0 画面。合計はサイトの画面数そのものになる
- これを出すのは、「13件目を公開したら画面が1枚増えた」が公開ページを開くまで
  分からないため。`?kind=` を付けた URL は、これより少ない画面になることがある
- 公開中のメンバーが1人なら、Team の行は「公開中が1人のあいだは、その人の
  プロフィール（N 画面）に置き換わる」と添え、N 画面にはその人の画面数を出す
  （紹介・技術・経歴から数える。`src/blocks.ts` の `memberScreenCount`。公開側の
  `memberScreens` と同じ `memberUnits` で開く）。下書きの行にも添える——公開したら
  何が出るかの知らせなので
- フォームの hint には「· 1画面 N 件 · 1画面 M 字まで」を添える。`perScreen` を
  変える口は作らない
- 行から**公開／下書きを直接切り替えられる**（`POST /admin/blocks/:id/publish`）。
  中身を触らないので検査もしない。編集フォームからの保存も、「公開する」を外した
  ものは中身を検査しない——検査すると、上限より前に保存された長い中身を持つ行が
  「引っ込めることすらできない」行き止まりになり、残る手が本文ごと削除だけになる
- ヘッダから公開ページを開ける。「サイトを見る ↗」は入口、「全体を1ページで見る ↗」
  は `/all`（公開側からは柱の足元と入口の帯の下の2本。足元は 899 以下で畳まれる）
- 何も置いていないときは、既定の並びで出している旨と「この並びから始める」だけを出す。
  **「足す」はまだ出さない**。今そこに見えている4節は既定の並びで、行としては
  存在しない。先にそれを行にしてから触らせる
- 「足す」には、まだ置いていない決まった中身のもの＋打ち込むもの全種が並ぶ。
  決まった中身のものは押せばすぐ置かれ、打ち込むものはフォームへ進む
- 「外す」は確認を挟む。決まった中身のもの（Projects など）を外しても登録は消えない。
  `blocks.ts` から消えた種類の行も外せる（読む側が無視するだけでは、一覧に残り続ける）

### 見た目

サイト全体の姿を、決め打ちの組み合わせから選ぶ。1画面で3つを選び、保存すると
すぐ公開ページに出る（下書きは無い）。

| 選ぶもの | 選択肢 | 効く場所 |
| --- | --- | --- |
| 骨格 | 左サイドバー / 中央寄せ / 雑誌風 | ページの組み立て方。狭い画面ではどれも1列に畳む。中央寄せと雑誌風は 900 以上でも柱を上の帯にする（中央寄せは2段で、著作権表示を出さない。雑誌風は1段で、名札の行・目次・足元の縦の中心をそろえる）。中央寄せが中央に組むのは入口・締め・ひとことで、節の見出しは本文の列と同じ左に立てる。雑誌風は「見出しを大きく取り」——入口の大見出しも節の見出しも1段大きく、カードのサムネイルは 4:1 |
| アクセント色 | アイリス / ヴァイオレット / エンバー / ミント / スカイ / ローズ | リンク・選択中の印・実績値・入口の月 |
| 書体 | ゴシック / 明朝 / 等幅 | 見出しだけ。本文は読みやすさを優先して据え置く |

選べる値は `src/theme.ts` が正。実際に姿を変えるのは `public/app.css` の
`[data-layout]` などで、**両方に足さないと「選べるのに何も変わらない」ものができる**。
保存済みの値が選択肢から消えていたら、既定（左サイドバー・アイリス・ゴシック）で描く。

## 画面の状態

どれも JavaScript なしで、1往復で成立する。

| 状態 | 出る場所 | 出し方 |
| --- | --- | --- |
| 入力エラー | フォーム | 項目のそばに1行。**打った内容は残す** |
| ログインのやり直し | ログイン | 提供元で断った（「ログインを取りやめました」）・state が合わない / 切れた / 別のタブで始めた・提供元が断った。`?error=` の決まった札だけを読み、文言はサーバーが持つ |
| 入れないアカウント | ログインの戻り | 403。そのアカウント自身の提供元 ID と、持ち主なら直す設定の名前（`OWNER_GITHUB_ID` など）を出す。Google で未確認のアドレスはそう言う |
| 提供元の障害 | ログインの戻り | 502。「GitHub との通信に失敗しました」。トークンは画面にもログにも出さない |
| すべての端末からログアウトした | ログイン | `?out=all` を読んで帯を1本 |
| 一覧が空 | 管理の一覧 | 空の表を出さず、「＋ 最初の…を追加」だけ置く |
| 絞り込みで0件 | Projects の画面 | ピルは残し、1行だけ出す。ピルはリンクなので、遷移した先でも外す手が画面に残る |
| 保存完了 | 一覧・構成・見た目 | `?saved=1` を読んで帯を1回だけ。下書きの保存（`?saved=draft`）は「サイトにはまだ出ていません」まで言う |
| 置けないブロック | 構成 | 400。同じ種類を2つ置こうとしたとき、知らない種類のとき、動かす向きが不明なとき |
| 出せない中身 | ブロックフォーム | 400。リンク集は URL の形まで見る（「公開」なのに出ない行を作らない）。**長さも見る**——[下の表](#長さの上限)。**下書きに戻す保存では見ない** |
| 重なった恒久リンク | Item フォーム | 400。`slug` は1つの作品を指すので、自動で `-2` を振らずに人に直してもらう |
| 代替テキストの無い画像 | Item フォーム | 公開の保存だけ 400。作品のページではその画像が作品の見た目を伝える唯一の手段。画像を選んで弾かれたときは「画像はまだ保存していません」と添える（ファイルの欄は描き直せない。Member フォームのアバターも同じ） |
| 受け取れない画像 | Item フォーム・Member フォーム | 400。中身が PNG・JPEG・WebP・AVIF・GIF のどれでもない（SVG・HEIC・名乗りと中身が違うもの）か、1MB を超える。下書きでも止める |
| 受け取れない URL | Item フォーム（リンク）・Member フォーム（GitHub） | 400。リンクは「2 行目の URL は…」「1 行目はラベルと URL の両方を…」と何行目かで言い、その行の欄に印。GitHub は `https://` から。公開ページでも同じ検査で落とす（保存と描画の2か所）ので、「保存できたのにサイトに出ない」行を作らない。下書きでも止める |
| 選べない見た目 | 見た目 | 400。帯を1本出し、保存はしない |
| 削除の確認 | 削除確認 | 対象名と、一緒に消えるものの件数。「非公開にする」逃げ道も添える |

### 長さの上限

数えるのは**割ったあとの1画面に出る字数の合計**で、割る前の単位（1段落・1行）では
ない——単位で見ていたころは、規則どおり空行で分ければ `perScreen` 倍がそのまま
通っていた。画面に文字として出るものだけを数える（見出しは数えず、リンク集の URL も
数えない）。数は `src/blocks.ts` の `maxChars` / `MAX_CHARS` が正。

| 書く場所 | 上限 | 備考 |
| --- | --- | --- |
| メモ | 1画面 400 字 | 1画面 3 段落 |
| いま | 1画面 250 字 | 1画面 10 件 |
| 数字 | 1画面 160 字 | 1画面 6 件 |
| リンク集 | 1画面 160 字 | 1画面 10 件。URL は数えない |
| できごと | 1画面 250 字 | 1画面 5 件 |
| ひとこと | 一文と添え書きの合計 300 字 | 一文だけは別に 120 字——これは収まるかどうかではなく「大きく出る一文」という文言の決まり |
| 作品の説明文 | 100 字 | カードは行数で止める（`--card-lines`）。600 以上は 100 字が切れずに出る6行、電話の幅は2行で 42 字まで。hint はその2つを両方出す |
| 作品の本文 | 60 字・1段落 | 作品のページ1枚に全段落が出る。いちばん重い作品（説明 100 字・画像・実績値・タグ・行き先4本）で測った。縛っているのは指の 390x844（1段落 66 字まで閉じる。2段落にすると 26 字）。以前は 130 字・2段落（13px の段落で測った数） |
| 紹介文 | 400 字・3段落 | 同じ字数でも空行が高さを取るので、段落の数にも上限がある（6段落なら 315 字まで）。以前は 450 字・6段落 |

上限は保存を押す前に見える（ブロックの中身の欄には「1画面 N 件 · 1画面 M 字まで」、
作品の説明文・本文と紹介文には `maxlength` と字数）。`maxlength` はブラウザ側の目安で、
保存してよいかを決めるのはいつもサーバー側の検査のほう。

数はすべて実測で決めた。測り方は「節の弁が1pxも開かない最大」で、骨格3 × 書体3 ×
設計サイズ3（390x844 と 768x1024 は指）の27通り。同じ字数でも1行に寄せたほうが高く
なるので、均等に割った形と寄せた形の両方で測り、厳しいほうを採る。文は実際の文に
近い和文で測る（段落は文節で折れるので、同じ字を並べた文より行が増える）。**上げたくなったら CSS ではなく、この27通りを
測り直すこと。** 測るときは自由文ブロックを1つだけ公開する（まとめて公開すると目次が
伸びて柱が膨らみ、数がずれる）。

## 静的ファイル

Worker より先に配られる（`public/`）。

| パス | 中身 |
| --- | --- |
| `/app.css` | 全画面のスタイル |
| `/assets/…` | ロゴ、アバターの初期画像、サイトの `og:image`（作品のページで画像がある作品は、その作品の画像） |

**ここに `robots.txt` や `sitemap.xml` を置かないこと。** どちらも Worker が
公開ページと同じ式から組み立てていて、`public/` に同じ名前のファイルを置いた瞬間に
静的なほうが勝ち、数え上げが静かに死ぬ。

JavaScript のファイルは無い。公開ページが読み込む `<script src>` は0本で、
絞り込みもページめくりもサーバーと URL だけで成立する。
