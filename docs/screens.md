# 画面一覧

公開は6種類（トップの連なり・全体・メンバー個別の連なり・作品1件・機械に読ませる
2本・画像）で、画面の数は構成しだいに変わる。管理が 12 画面。ルートの実体は
`src/routes/public.tsx` と `src/routes/admin.tsx`。

## 公開側

誰でも見られる。出すのは `published = 1` の行だけ。骨格・色・書体は、管理の
[見た目](#見た目)で選んだものがそのまま全ページに効く。

公開ページは**1画面に1つぶんだけを収め、ページそのものはスクロールしない**。
入りきらないぶんは次の URL に送る。移動は普通のフルページ遷移で、JavaScript は
1バイトも持たない。縦に伸びてよいのは `/all` だけ。

表は `src/routes/public.tsx` の**登録順そのまま**。`/:screen` と `/:screen/:page`
は1語・2語の URL を何でも拾う catch-all なので、固定の URL は必ずその前に並ぶ。

| 画面 | パス | 出すもの | 中身が無いとき |
| --- | --- | --- | --- |
| 全体 | `GET /all` | 公開中のブロックを全部、1ページに縦に積んで | その節ごと出さない。見出しだけ残さない |
| トップ | `GET /` | 連なりの先頭の画面（ふつうは Hero） | 置いたものが全部空なら「まだ何も置いていません」 |
| メンバー個別 | `GET /members/:slug` | 名乗りと、この人の一覧への帯 | 下書き・不明な slug は 404 |
| メンバーの画面 | `GET /members/:slug/:screen` | `about` `skills` `career` `contact` | 書いていない画面は 404 |
| その画面の続き | `GET /members/:slug/:screen/:page` | 2画面目から（`/members/okazaki/career/2`） | 範囲の外は 404。`…/1` は `…` へ 303 |
| 作品1件（app） | `GET /apps/item/:slug` | その作品だけの画面 | 下書き・不明な slug は 404 |
| 作品1件（work） | `GET /works/item/:slug` | 同上 | 1語目と種類が食い違う URL も 404 |
| クローラへの指示 | `GET /robots.txt` | `text/plain`。`/admin/` だけ外す | — |
| URL の一覧 | `GET /sitemap.xml` | `application/xml`。公開中の画面を数え上げる | — |
| 画像 | `GET /images/avatars/…` | KV に入れたアバター | 該当なしは 404 |
| 画面 | `GET /:screen` | そのブロックの1画面目（`/apps` `/works` `/team` …） | 無い画面名は 404 |
| 画面の続き | `GET /:screen/:page` | 2画面目から（`/apps/2`） | 範囲の外は 404。`/apps/1` は `/apps` へ 303 |

作品の恒久リンクが3語なのは、catch-all（1語・2語）と取り合わないようにするため。
2語（`/apps/<slug>`）にすると、めくる先の番号と作品の名前が同じ位置で取り合い、
slug が数字の作品を作れなくなる。

404（未定義の URL）と 500（例外）は、ルートではなく `src/index.tsx` の
`notFound` / `onError` が受ける。マークと戻り導線だけを出す。

登録順は散文だけでなくテストが守っている（`test/public.test.ts` の「URL の登録順」が
Hono の `publicRoutes.routes` を読み、catch-all が最後の2本だけであることを見る）。

絞り込みは query で足す。どの画面にも付けられる。

| query | 効く先 | 例 |
| --- | --- | --- |
| `?platform=<key>` | Apps だけ（work は `platform_key` を持たない） | `/apps?platform=ios` |
| `?member=<slug>` | Apps と Works の両方 | `/works?member=okazaki` |

知らない key・公開中に居ない slug は、絞り込みとして扱わず全件を出す。ピルに
並ばないもので絞り込むと、外す手が画面から無くなるため。同じ理由で、公開中が
1人のサイトでは `?member=` を読まない（名前のピルは2人以上いるときだけ並ぶ）。絞り込みはページャにも
目次にも同じものが付いて画面をまたいで効き、canonical には付けない
（同じ中身の取り出し方なので、組み合わせのぶんだけ URL を数えさせない）。

`all` は画面の名前としての予約語。決まった中身のブロックの key
（`hero` `apps` `works` `team` `contact`）とも、打ち込むブロックの `block-<id>`
とも衝突しない。**固定のルートは `/:screen` より前に登録する。** あとから下に
足すと、一致が catch-all に吸われて、そのページだけが静かに 404 になる。

先頭の画面は `/` と `/<slug>`（`/hero`）の2つで開ける。canonical は `/` に
そろえ、2つ目からはその画面の URL が正。題も説明文も画面ごとに変える（同じ題の URL が
並ぶと、履歴から選び直せない）。**構造化データ（JSON-LD）は連なりの先頭の画面にだけ
載せる**——同じ名乗りが画面の数だけ並ぶと、どれが本体か決められない。

`<meta name="description">` と `og:description` は、**その画面に実際に出ている文字**
から作る（`src/routes/public.tsx` の `DESCRIPTION_MAX` は 110 字。超えたら末尾を `…`
にして切る）。入口＝名乗り、Apps＝件数とピルとその画面のカード名、Works＝件数と
カード名と実績値、Team＝名前と職種、Contact＝リードの一文、打ち込んだブロック＝
見出しとその画面の行、`/all`＝実際に描いた節の名前。固定の文を書かないのは、
中身を足した日に説明文だけ古くなるため。

共有カードの画像（`og:image`）はサイトに1枚（`/assets/avatar.png`、144x144 PNG）。
推奨の 1200x630 に届かないので、貼り先は大きなカードではなく小さな正方形の
サムネイルを出す。**足りないもの: 1200x630 の PNG 1枚**——置いたら
`src/ui/Layout.tsx` の `OG_IMAGE` の3行と `twitter:card` の1語を差し替えるだけでよい。

### 機械に読ませる2本

`/robots.txt` は `User-agent: *` / `Allow: /` / `Disallow: /admin/` と、絶対 URL の
`Sitemap:` 行。相対では書けない（クローラが読まない）。

`/sitemap.xml` は手で並べた表を持たず、公開ページと同じ式から数え上げる——
トップの画面（`siteSteps` の canonical）／全体ページ `/all`／個人ページ
（`memberScreens`。割った2画面目も出る）／作品の恒久リンク（`itemHref`）の4つ。
載らないのは下書き・0件で消えた節・絞り込み付きの URL・`/admin`。同じ URL は1度だけ。
**新しい連なりを足したら、この4行にも1行足すこと。**

どちらも Worker のルートで返す。`public/robots.txt` や `public/sitemap.xml` を
置いてはいけない——`public/` は Worker より先に配られるので、置いた瞬間に静的な
ほうが勝ち、数え上げが静かに死ぬ。

### トップの構成

トップは「決まった部品（ブロック）の連なり」で、管理の[構成](#構成)から
置く・外す・前後に動かす。部品の見た目は変えられないので、どう並べても同じ設計の
中に収まる。何も置いていなければ Hero → Apps → Works → Team → Contact の順。

1つのブロックは**件数しだいで何画面にもなる**。1画面あたりの件数（`perScreen`）と
字数（`maxChars`）は `src/blocks.ts` が正で、割るのは `src/lib/paginate.ts`。CSS の
値ではなく件数なので `:root` には置かない。管理画面からも変えられない（見た目を
変える口にしないため）。Apps / Works の**列の数**もここから出る——`perScreen` を
`style="--cols:2"` でそのまま渡すので、1画面ぶんが必ず1行に並ぶ（600 未満は1列）。

| ブロック | 中身 | 出す条件 | 1画面あたり | 備考 |
| --- | --- | --- | --- | --- |
| Hero | 名乗り（1人なら名前と肩書き、それ以外はサイト名）とリード（`src/site.ts`） | 常に | 画面まるごと | 目次には載らない。標語は置かない。月を右上に、字を画面の下に寄せる。リードの下に一覧への帯（丸い札）が付く |
| Apps | 公開中の app | 1件以上 | 2 件 | 絞り込みピルは、実在するプラットフォームだけ並ぶ |
| Works | 公開中の work | 1件以上 | 2 件 | 実績値は1項目に1つだけ |
| Team | 公開中のメンバー | 1人以上 | 6 人 | **1〜2人は横長カード、3人以上はグリッド**。人数で決める、画面幅では決めない |
| Contact | 連絡先（`src/site.ts`） | 常に | 画面まるごと | GitHub のプロフィールもここに常設 |
| ひとこと | 大きな一文と添え書き（段落は何段でも） | 一文がある | 300 字 | 目次には載らない。一文はその画面の `h1` |
| いま | 「何を \| 補足」の箇条書き | 1行以上 | 10 件 / 250 字 | |
| 数字 | 「値 \| 単位 \| 説明」のタイル | 1行以上 | 6 件 / 160 字 | 2〜4つが収まりがよい |
| リンク集 | 「ラベル \| URL \| 補足」 | 有効な URL が1行以上 | 10 件 / 160 字 | `https://` `mailto:` `/` 以外は落とす。`//host` は外部 URL なので通さない。URL は字数に数えない |
| できごと | 「年月 \| 何を \| 補足」 | 1行以上 | 5 件 / 250 字 | 個人ページの経歴と同じ形 |
| メモ | 段落の文章 | 1段落以上 | 3 段落 / 400 字 | 見出しは無くてもよい。無ければ目次にも載らない |

上の5つは1つずつしか置けない。下の6つはいくつでも置ける。

目次は、実際に出た節だけを、出た順に載せる。**番号（01〜）は振らない**——目次の番号は
ブロックの並び順なので `/apps` でも `/apps/3` でも動かず、画面の底のページャが出す数と
2組並ぶと、同じ数え上げに見える。数えるのはページャ1つに寄せる。
ブロックの2画面目以降を見ているあいだも、その見出しに印（`aria-current="page"`）が残る。

**ページャが数えるのは節の中**（`Apps  2 / 3`）で、サイト全体の通し番号ではない。
全体で数えていたころ（`01 · 07`）は3つ困っていた——柱の「Apps」を押しても Apps が
3画面あることがどこにも出ない、「次 →」が節の中の移動と節をまたぐ移動を兼ねていて
`/apps/3` で押すと予告なく Works に出る、そして**絞り込みが無関係な画面の番号を動かす**
（Apps を macOS で絞ると 3画面が1画面になり、`/contact` の番号が `07` から `05` へ。
実測で、`/contact` と `/contact?platform=macos` の違いはその数字だけだった）。

めくる先は今までどおり連なり全体なので、「次」を押し続ければサイトを一周できる。
変わったのは数え方と、**節をまたぐときに行き先を名乗る**こと（`← 前` が
`← Apps` になる）。名前を持たない節（Hero・ひとこと）は1枚しか無いので数を出さない。

「画面まるごと」のブロックに2画面目は無い。1つの段落や1つの文はどこにも割れない
ので、そちらは長さの上限で受ける（[出せない中身](#画面の状態)）。

節そのものが弁（`overflow: auto`）なので、割られた画面の節には `tabindex="0"` が
付き、見出しを持つものは `role="region"` と見出しと同じ `aria-label` を持つ。
`main` の直接の子になる箱は `src/ui/components.tsx` の `Screen` / `Hero` だけが作る。

### 全体ページ

`GET /all` は、公開中のブロックを全部1ページに縦に積んで出す。画面ごとに割らず、
一覧も全件を出す（`perScreen` を使わない唯一の公開ページ）。**canonical は自分自身**。
節は `#apps` のような id で並ぶので、画面ごとの URL（`/apps`）と同じ節をアンカーでも
指せる。この1本が受け持つのは次の役目。

- 印刷。1回で全部が紙に載る
- Ctrl-F とブラウザ翻訳。ページをまたがずに全文を探せる・訳せる
- オーナーが全体を通しで点検する
- 画面ごとの組み立てが効かない環境での退避先

canonical を `/` にしていたころは、中身が全部ある唯一のページを「作品を1件も
含まないトップの複製」として申告していた——index に載るのが中身の薄い準重複の
画面ばかりで、完全版が載らない、という逆の形になる。画面ごとの URL はそれぞれ
自分を正と名乗り、`/all` も自分を名乗る。

縦に伸びてよい唯一の公開ページなので、画面に収める外枠はここには当てない
（目印は `body[data-whole]`）。弁が無く、ページ自身が動くので、節に `tabindex` も
付けない。

行く道は2本ある。公開側は柱の足元の「全体を1ページで見る ↗」、管理側は「構成」の
ヘッダの同じ文言。足元の1本は 899 以下では畳まれる（`.rail__footer` ごと）ので、
スマホの幅では画面から消える——`sitemap.xml` には載るので検索からは届く。

### メンバー個別ページ

個人ページもトップと同じ規則の連なりで、1画面 = 1ドキュメント。件数の軸も同じ形で
持つ（`src/blocks.ts` の `MEMBER_PER_SCREEN`。割るのは同じ `src/lib/paginate.ts`）。

| パス | 出すもの | 出す条件 | 1画面あたり |
| --- | --- | --- | --- |
| `/members/<slug>` | 名乗り（大見出し）と、この人の一覧への帯 | 常に | 画面まるごと |
| `/members/<slug>/about` | 紹介文 | 常に。空なら「準備中です」 | 6 段落 |
| `/members/<slug>/skills` | 技術 | 書いてあるときだけ | 3 塊 |
| `/members/<slug>/career` | 経歴 | 書いてあるときだけ | 5 行 |
| `/members/<slug>/contact` | 連絡先（無ければサイトの宛先） | 常に | 画面まるごと |

割れた2画面目からは `/members/<slug>/<screen>/<page>`（例
`/members/okazaki/career/2`）。1画面目は `…/<screen>` ひとつに寄せてあり、`…/1` は
そこへ 303。`/01` や `/abc` は 404。文法はトップの `/:screen/:page` と同じで、
読み方も同じ関数（`readPage`）が持つ。

数はどれも発明ではなく導出してある。About は書く側の上限
（`MAX_CHARS.memberBioParagraphs` = 6。「6段落なら弁が1pxも開かない」という実測
そのもの）、Career は同じ `<Timeline>` と `.career` で描く「できごと」ブロックの
`perScreen`。Skills の 3 だけは 27通りの実測ではなく、app.css が「技術の3つの塊」と
呼んでいる今日の姿に合わせた保守的な数。**`skillsText` と `careerText` には字数の
上限がまだ無い**——1つの塊・1行が極端に長い場合だけが残った穴で、数を決めるには
骨格3 × 書体3 × 設計サイズ3 の実測が要る。

- 書いていない画面は作らない。URL も目次もページャも一度に消える（404）。
  技術も経歴も書いていない人は3画面。**5枚固定ではない**——紹介7段落・技術4塊・
  経歴6行のような中身では6枚以上になる
- About を空でも残すのは、まだ書いていないのか URL を間違えたのかを、読み手が
  見分けられるようにするため
- 入口は `/members/<slug>` ひとつ。1枚目に2つ目の URL（`…/hero`）は作らない
- Apps / Works のカードはここに複製しない。帯と目次の「Apps · Works」から
  `/apps?member=<slug>` へ送り、一覧をその人で絞り込んだ1画面目に着かせる。
  Apps が0件の人は `/works?member=<slug>` へ。どちらも0件なら帯ごと出さない。
  **トップに置いていない節へは送らず、その件数も数えない**（Works を外した
  サイトでは `Apps 2` だけ）。1人のサイトでは `?member=` を付けない
- 目次は About → Skills → Career → Contact を順に並べ、連なりの外にある
  「Apps · Works」を最後に置く。**1枚目は目次に載らない**（トップの Hero と同じ
  扱い）。1枚目へ1押しで戻れるのはページャの「← 前」だけ——左上のロゴは
  サイトのトップ `/` へ行く
- 柱の名前は `<p class="identity__name">`。`h1` は `main` の側にある（柱はどの画面
  にも同じ文字列で出るので、`h1` にすると全画面の見出しが同じになる）。1枚目の
  `h1` は `<h1 class="hero__headline">`
- 900 未満では名札を横帯に畳む。顔・所在地・肩書きはそこで畳まれる（`/all` と
  900 以上の柱では今までどおり出る）。肩書きは Team のカード・`<title>`・
  `description`・JSON-LD の `jobTitle` に残る
- 構造化データは `Person`。公開中が1人のあいだは `worksFor` を出さない——トップが
  同じ URL を `Person` として名乗っているので、書くと1つの URL が2つの型を持つ

### 作品1件のページ

`GET /apps/item/<slug>` と `GET /works/item/<slug>`。一覧の URL（`/apps/3`）は
「いまの並びの3枚目」でしかなく、並べ替え・公開の切り替え・追加のたびに 200 の
まま別の作品を指す。貼れる URL はこちら。

- 出る条件は「その作品が公開中」の1つだけ。**トップの構成には依らない**——Apps の
  節を外しても、貼られた作品のリンクは死なない
- 下書きは 404。1語目と種類が食い違う URL（`/works/item/<app の slug>`）も 404
  （同じ作品に2つの URL を作らない）
- 連なりの外にある1枚なので**ページャは出さない**。目次はトップと同じ画面の列を
  出し、印はその作品が載っている一覧（Apps か Works）に付く。戻る道は目次だけ
- 新しい見た目は持たない。`SectionHead` / `Note`（`.bio`）/ `Numbers` / `Tags` /
  `LinkList` の既存部品だけで組んであり、`public/app.css` は1行も増えていない。
  説明文にカードの `<p>` を使わないのは、あちらが `--card-lines` で2行に切られるため
- 構造化データは `CreativeWork`（name / url / description）。`<title>` と `og:title`
  は「&lt;作品名&gt; — Noctifex」、canonical と `og:url` は自分の URL
- 一覧のカードの題がこの URL へのリンク（`/all` のカードも同じ）。`slug` の無い
  作品は素の題のまま——当てにならない URL を出すくらいなら出さない
- 「担当」（個人ページへのリンク）は、カードの担当者名と同じ条件で出す。2人以上
  いるとき、または Team の節を置いていないとき（そうしないと個人ページへの道が
  トップから1本も無くなる）

## 管理側

`/admin/*`。ログインが要る。書き込みは `Origin` も確認する（ログイン画面を含む）。

| 画面 | パス | 認証 | 役割 |
| --- | --- | --- | --- |
| 入口 | `GET /admin` | 要 | `/admin/members` へ 303 |
| ログイン | `GET /admin/login` | 不要 | フォーム。`?next=` を hidden で持ち回す |
| ログイン実行 | `POST /admin/login` | 不要 | 成功で Cookie を発行し、`next` の画面（`/admin/` の中だけ）か `/admin/members` へ |
| ログアウト | `POST /admin/logout` | 要 | セッションを消す |
| 初期設定 | `GET`/`POST /admin/setup` | 不要 | **users が空で、かつ `SETUP_TOKEN` が一致するときだけ**。owner を1件作り、そのままログインして `/admin/members` へ。以降は 404 |
| Members 一覧 | `GET /admin/members` | 要 | 行に 公開/下書き・並び順・編集・削除。公開中の行には「サイトで見る ↗」 |
| Member フォーム | `GET /admin/members/new`<br>`GET /admin/members/:id/edit` | 要 | 追加と編集で同じテンプレート |
| Member 保存 | `POST /admin/members`<br>`POST /admin/members/:id` | 要 | 成功で `?saved=1`（下書きなら `?saved=draft`）を付けて一覧へ |
| Member 削除 | `GET /admin/members/:id/delete`（確認）<br>`POST` 同 URL（実行） | 要 | 確認画面を必ず挟む。キャンセルは来た画面へ（編集から来たら `?from=edit` で編集へ） |
| Items 一覧 | `GET /admin/items?type=app\|work` | 要 | Apps / Works をタブで切り替え。行に恒久リンクの URL（無ければ「恒久リンクなし」） |
| Item フォーム | `GET /admin/items/new?type=…`<br>`GET /admin/items/:id/edit` | 要 | `type` で欄が変わる（app はプラットフォーム、work は区分と実績値）。恒久リンクの `slug` もここ |
| Item 保存 | `POST /admin/items`<br>`POST /admin/items/:id` | 要 | タグとリンクは総入れ替え。`slug` の重なりは 400 で戻す。成功で `?saved=1`（下書きなら `?saved=draft`） |
| Item 削除 | `GET /admin/items/:id/delete`（確認）<br>`POST` 同 URL（実行） | 要 | 一緒に消えるタグ・リンクの件数を出す。キャンセルは Member と同じく来た画面へ |
| 構成 | `GET /admin/blocks` | 要 | 公開ページの画面の連なり。行ごとに ↑↓・公開/下書き・編集・外す・**「N 画面」**。頭に合計。ヘッダに「サイトを見る ↗」と「全体を1ページで見る ↗」。下に「足す」のカタログ |
| ブロック追加 | `POST /admin/blocks`（決まった中身のもの）<br>`GET /admin/blocks/new?type=…` → `POST /admin/blocks`（打ち込むもの） | 要 | Contact の手前に足され、その行（`#block-<id>`）へ戻る。打ち込むものは下書きから始まる |
| ブロックフォーム | `GET /admin/blocks/:id/edit`<br>`POST /admin/blocks/:id` | 要 | 決まった中身のものは「公開する」だけ |
| ブロック公開切替 | `POST /admin/blocks/:id/publish` | 要 | 一覧の行から公開／下書きを直接切り替える。中身は触らない |
| ブロック移動 | `POST /admin/blocks/:id/move`（`dir=up\|down`） | 要 | 並び順を 10 刻みで振り直し、動かした行（`#block-<id>`）へ戻る |
| 既定の並び | `POST /admin/blocks/init` | 要 | 何も置いていないときだけ5つを入れる |
| ブロック削除 | `GET /admin/blocks/:id/delete`（確認）<br>`POST` 同 URL（実行） | 要 | 決まった中身のものは、外しても登録した項目は消えない |
| 見た目 | `GET /admin/appearance`<br>`POST` 同 URL（保存） | 要 | 骨格・アクセント色・書体を選ぶ。サイト全体に効く |

どの画面も、左ナビの足元の「サイトを見る ↗」から公開ページを別タブで開ける。

一覧・フォーム・確認の3種類だけで、Members・Items・構成をまかなっている。
一覧にフォームを同居させないのは、「どの行を編集中か」が読めなくなるため。
見た目だけは一覧を持たない。選ぶものが3つで、増えも減りもしないため。

### 構成

公開ページの画面の連なり。行の ↑↓（読み上げは「前へ / 後ろへ」）はそれぞれ
小さな `POST` フォームで、押すと 303 で同じ一覧に戻る（JavaScript は使わない）。

- 行ごとに「**N 画面**」、一覧の頭に「合計 N 画面」を出す。**読み取り専用の
  知らせで、ここから件数は変えられない**。数え方は公開ページと同じ
  （`src/blocks.ts` の `perScreen` と `src/lib/paginate.ts`。中身を単位に開く式も
  `blockLines` / `blockTexts` / `blockUnitCount` の1本を公開側と共有する）。下書きと、
  中身が0件のものは 0 画面。合計はサイトの画面数そのものになる
- これを出すのは、「13件目を公開したら画面が1枚増えた」が公開ページを開くまで
  分からないため。`?platform=` を付けた URL は、これより少ない画面になることがある
- フォームの hint には「· 1画面 N 件 · 1画面 M 字まで」を添える。`perScreen` を
  変える口は作らない
- 行から**公開／下書きを直接切り替えられる**（`POST /admin/blocks/:id/publish`）。
  中身を触らないので検査もしない。編集フォームからの保存も、「公開する」を外した
  ものは中身を検査しない——検査すると、上限より前に保存された長い中身を持つ行が
  「引っ込めることすらできない」行き止まりになり、残る手が本文ごと削除だけになる
- ヘッダから公開ページを開ける。「サイトを見る ↗」は入口、「全体を1ページで見る ↗」
  は `/all`（公開側からは柱の足元にしか道が無く、そこは 899 以下で畳まれる）
- 何も置いていないときは、既定の並びで出している旨と「この並びから始める」だけを出す。
  **「足す」はまだ出さない**。今そこに見えている5節は既定の並びで、行としては
  存在しない。先にそれを行にしてから触らせる
- 「足す」には、まだ置いていない決まった中身のもの＋打ち込むもの全種が並ぶ。
  決まった中身のものは押せばすぐ置かれ、打ち込むものはフォームへ進む
- 「外す」は確認を挟む。決まった中身のもの（Apps など）を外しても登録は消えない。
  `blocks.ts` から消えた種類の行も外せる（読む側が無視するだけでは、一覧に残り続ける）

### 見た目

サイト全体の姿を、決め打ちの組み合わせから選ぶ。1画面で3つを選び、保存すると
すぐ公開ページに出る（下書きは無い）。

| 選ぶもの | 選択肢 | 効く場所 |
| --- | --- | --- |
| 骨格 | 左サイドバー / 中央寄せ / 雑誌風 | ページの組み立て方。狭い画面ではどれも1列に畳む |
| アクセント色 | アイリス / ヴァイオレット / エンバー / ミント / スカイ / ローズ | リンク・選択中の印・実績値・入口の月 |
| 書体 | ゴシック / 明朝 / 等幅 | 見出しだけ。本文は読みやすさを優先して据え置く |

選べる値は `src/theme.ts` が正。実際に姿を変えるのは `public/app.css` の
`[data-layout]` などで、**両方に足さないと「選べるのに何も変わらない」ものができる**。
保存済みの値が選択肢から消えていたら、既定（左サイドバー・アイリス・ゴシック）で描く。

## 画面の状態

どれも JavaScript なしで、1往復で成立する。

| 状態 | 出る場所 | 出し方 |
| --- | --- | --- |
| 入力エラー | フォーム | 項目のそばに1行。**打った内容は残す** |
| ログイン失敗 | ログイン | 「メールアドレスかパスワードが違います」。どちらが違うかは言わない |
| 試行回数の制限 | ログイン | 5回失敗で 15 分。429 を返す |
| 一覧が空 | 管理の一覧 | 空の表を出さず、「＋ 最初の…を追加」だけ置く |
| 絞り込みで0件 | Apps の画面 | ピルは残し、1行だけ出す。ピルはリンクなので、遷移した先でも外す手が画面に残る |
| 保存完了 | 一覧・構成・見た目 | `?saved=1` を読んで帯を1回だけ。下書きの保存（`?saved=draft`）は「サイトにはまだ出ていません」まで言う |
| 置けないブロック | 構成 | 400。同じ種類を2つ置こうとしたとき、知らない種類のとき、動かす向きが不明なとき |
| 出せない中身 | ブロックフォーム | 400。リンク集は URL の形まで見る（「公開」なのに出ない行を作らない）。**長さも見る**——[下の表](#長さの上限)。**下書きに戻す保存では見ない** |
| 重なった恒久リンク | Item フォーム | 400。`slug` は1つの作品を指すので、自動で `-2` を振らずに人に直してもらう |
| 選べない見た目 | 見た目 | 400。帯を1本出し、保存はしない |
| 削除の確認 | 削除確認 | 対象名と、一緒に消えるものの件数。「非公開にする」逃げ道も添える |

### 長さの上限

数えるのは**割ったあとの1画面に出る字数の合計**で、割る前の単位（1段落・1行）では
ない——単位で見ていたころは、規則どおり空行で分ければ `perScreen` 倍がそのまま
通っていた。画面に文字として出るものだけを数える（見出しは数えず、リンク集の URL も
数えない）。数は `src/blocks.ts` の `maxChars` / `MAX_CHARS` が正。

| 書く場所 | 上限 | 備考 |
| --- | --- | --- |
| メモ | 1画面 400 字 | 1画面 3 段落 |
| いま | 1画面 250 字 | 1画面 10 件 |
| 数字 | 1画面 160 字 | 1画面 6 件 |
| リンク集 | 1画面 160 字 | 1画面 10 件。URL は数えない |
| できごと | 1画面 250 字 | 1画面 5 件 |
| ひとこと | 一文と添え書きの合計 300 字 | 一文だけは別に 120 字——これは収まるかどうかではなく「大きく出る一文」という文言の決まり |
| 作品の説明文 | 100 字 | カードは2行止め（`--card-lines`）。設計サイズで全部読めるのは 46 字までで、hint はその2つを両方出す。上限を「切られない長さ」ではなく「誰にも届かない長さ」にしてあるのは、既に保存されているものが編集のたびに弾かれないようにするため |
| 紹介文 | 450 字・6段落 | 同じ字数でも空行が高さを取るので、段落の数にも上限がある |

上限は保存を押す前に見える（ブロックの中身の欄には「1画面 N 件 · 1画面 M 字まで」、
作品の説明文と紹介文には `maxlength` と字数）。`maxlength` はブラウザ側の目安で、
保存してよいかを決めるのはいつもサーバー側の検査のほう。

数はすべて実測で決めた。測り方は「節の弁が1pxも開かない最大」で、骨格3 × 書体3 ×
設計サイズ3 の27通り。同じ字数でも1行に寄せたほうが高くなるので、均等に割った形と
寄せた形の両方で測り、厳しいほうを採る。**上げたくなったら CSS ではなく、この27通りを
測り直すこと。** 測るときは自由文ブロックを1つだけ公開する（まとめて公開すると目次が
伸びて柱が膨らみ、数がずれる）。

## 静的ファイル

Worker より先に配られる（`public/`）。

| パス | 中身 |
| --- | --- |
| `/app.css` | 全画面のスタイル |
| `/assets/…` | ロゴ、アバターの初期画像、`og:image` |

**ここに `robots.txt` や `sitemap.xml` を置かないこと。** どちらも Worker が
公開ページと同じ式から組み立てていて、`public/` に同じ名前のファイルを置いた瞬間に
静的なほうが勝ち、数え上げが静かに死ぬ。

JavaScript のファイルは無い。公開ページが読み込む `<script src>` は0本で、
絞り込みもページめくりもサーバーと URL だけで成立する。
